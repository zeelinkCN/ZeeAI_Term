# ZeeAI_Term v0.1.12

这一版的主题是**"把已经做出来的东西变准"**：AI 看板推倒重来（实体定义换成「AI 实例」，
面板从六块收成两块），启动不再闪白/重影，还有两个用户报障的修复 ——
**本机配了免密却连不上**（我们以前硬传 `-p 22 root@`，把你的 `~/.ssh/config` 顶掉了）
和**中文提示里冒出一个孤立的 `-`**。

> 升级方式：安装版「设置 → 检查更新 → 立即下载」；便携版下载新 zip 解压覆盖（覆盖前先关掉窗口）。
> 这一版**仍然只允许同时跑一个实例**（便携版与安装版共用 `%APPDATA%\ZeeAI-Terminal`）。

---

## 1. 启动：不闪白、不重影、不卡那一下

**用户报的原话**："启动瞬间一大一小两个相同画面重影 + 卡顿一下。"

**先量，再改。** 加了一个探针（`scripts/startup-probe.ps1`，按 100ms 连续抓窗口画面并比对哈希）
和一个截图脚本（`scripts/startup-capture.ps1`，把启动过程一帧一帧存成 PNG 来亲眼看）。
量出来的真相是：

- 窗口大约 **373ms** 就映射到屏幕上了，可那时 WebView2 **一帧都还没画** ——
  这段时间屏幕上留着的是**上一次那个窗口的残留**（所以看起来是"两个相同的画面，一大一小"）；
- 接着画出一片**白**，最后才是深色界面；一直到 **~1010ms** 画面才稳定。
  中间这 600 多毫秒，就是"卡顿一下"。

**改法**（三件事，互相补位）：

1. **两层深色底**：`tauri.conf.json` 给窗口设背景色 **+** 后端 `set_background_color()`
   给 **webview 层**也设一遍（只设窗口那层不够 —— 实测 webview 自己还是白的，这就是白闪的来源）；
2. **不依赖 JS 的静态启动屏**：写死在 `index.html` 里（深色底 + `ZeeAI Term / 正在启动…`），
   浏览器拿到 HTML 就能画，React 首屏画好后由 `src/main.tsx` 摘掉。
   于是"第一眼看到的一定是我们自己的画面"，而不是白板或上个窗口的残影；
3. **把重活推迟到首帧之后**（`src/startup.ts`）：看板扫描、时间线读取、rollout 快照轮询、
   静默更新检查、tmux 轮询、**WebGL 渲染器挂载**（它要栅格化整个字形图集，是首屏最贵的一步）
   统统等"真的 present 了一帧"（两次 rAF / 字体就绪）再做，再等主线程空下来执行，最多等 1.5 秒。
   只改**什么时候做**，不改行为。

顺手加了**启动计时**：每个阶段都会写一行到 `%LOCALAPPDATA%\com.zeeai.terminal\logs\startup-marks.log`
（`stage=… at_ms=… pid=…`）。单独写一个小文件是因为日志插件有缓冲，进程被强杀时最后几行会丢 ——
启动耗时是要拿数字说话的东西，不能靠运气。窗口还加了**居中**。

**试过、并且否掉的方案**：一开始想的是"窗口隐藏创建（`visible: false`）、等前端 ready 再 `show()`"。
**实测更差** —— Chromium 对隐藏窗口会推迟渲染，窗口虽然 250ms 就 `show()` 了，
但**第一帧要到 ~1.4s** 才出来，用户要对着一个空窗口干等一秒。
所以窗口最终仍然是**可见创建**的；`frontend_ready` 那条命令只做计时，`show()` 只是保险
（另有 5 秒兜底线程，万一窗口因故没显示也能出来）。

## 2. AI 看板 v2：实体定义错了，补丁是修不完的

**为什么要重做**：老看板把五套来源（herdr 第一手 / 远端 tmux+ps / 本机进程表 / WSL `ps` /
本应用账本 / rollout 日志）画成同一种卡，再用"两趟打补丁"的合并规则去逼近"一个实例一张卡"。
问题不在补丁写得不好，而在**主键里既掺了"环境/服务器/工具/目录"、又掺了"窗格"** ——
于是"同一目录下两个 codex 只剩一张卡"这种毛病只能一修再修。
完整口径写在 `docs/design-ai-board-v2.md`（**§10 是最终口径**，与其它节冲突时以 §10 为准），
另附一张可点的样品页 `docs/mockups/ai-board-v2.html`。

**这一版落地的**：

- **唯一实体 = 「AI 实例」**（后端 `src-tauri/src/core/ai_instance.rs`）：每条观测都带
  "**谁说的**"（证据来源）与"**多可信**"（第一手 / 推断）；实体主键 = 承载 + 环境 + 实例锚
  （herdr 窗格 / tmux 目标 / pid / 账本 id）。**合并逻辑只留一份实现**（在 Rust 侧）：
  前端把已经采集到的来源原样送进 `ai_instances`，合并/判状态由后端做 ——
  以前前端 JS 里那份合并（`taskKeyOf` + 第二趟并组）已经删掉；
- **面板只留两个区**：`需要你` + `运行中`；**最近完成 / 空闲各折成一行**（默认折叠，点开才渲染）；
  **承载健康只在异常时出现**（`herdr 服务：运行中 · N 个窗格` 这种正常状态不再常驻占位，
  但要查的时候在悬停/折叠里找得到）；
- **每张卡都有来源徽标 + 悬停证据说明**：写清"谁说的 · 多久前 · 能证明什么"，
  被承载能力闸门降级过的卡会显示"有来源声称它是 X"；
- **裸 SSH 永不显示「等你处理」**：进程扫描只能证明"有这么个进程在跑"，
  所以那张卡只写「运行中（**进程推断**，可能已卡住）」；`needs-you` 只由 herdr 第一手给出；
- **CMD 这类空承载不上板**（没跑 agent 的承载不占行，只在承载健康里可查）；
- **删掉独立的「最近任务 / 时间线」列表**：只留 `▸ 最近完成 N 项` 折叠一行，
  **数据照旧落盘**（不显示 ≠ 丢掉，将来做"历史/统计"另开一页）；
- **状态栏只留四件事**：`会话 · 连通性 · 需要你 N · 传输`。
  `UTF-8` / `xterm-256color` / 窗口尺寸收进**悬停**（以前它们常驻，挤掉了真正要看的东西）；
- **红点只认两条规则**（这是用户最在意的一条）：① **需要你** → 亮到**你处理为止**（打开面板不等于处理）；
  ② **这一轮跑完并停下** → 亮一个未读，**点开面板即清**。
  **不亮**：运行中、空闲、陈旧、**只产出文件但还没停**、探测不到。**同一实例同一轮只亮一次**
  （按轮次去重，反复轮询不会又冒出来）。
  设置里也相应拆成两个独立开关（`需要你处理时提醒` / `跑完一轮并停下时提醒`，**默认都开**），
  旧的那条总开关保留字段只为读得懂老配置，界面不再用它。

## 3. 修报障：本机配了免密，我们却连不上

**用户报的现象**："我在 `~/.ssh/config` 里配了别名和免密，别的工具都能连，就你这里要密码/连不上。"

**根因**：我们**永远显式传**端口和用户名（`-p 22` + `root@host`）——
这会**顶掉** `~/.ssh/config` 里的 `Port` / `User`。实测 `ssh -p 22 root@myalias` 解析出来是
`user root / port 22`，只有**只给别名**时 config 里的 `user / port / identityfile` 才会生效。

**改法**：端口和用户名**都可以留空**（留空 = "没说"），留空时我们**不传** `-p`、**不写** `user@`，
把这两项交给你的 `~/.ssh/config`。ssh / scp / 一次性命令三条路都同一套口径。
显式值仍然优先：你填了就是我们说了算（行为跟以前一模一样）。
界面上的占位符也跟着改了 —— 主机那栏写「**IP 或 ~/.ssh/config 里的别名**」，
端口/用户写「留空则用 `~/.ssh/config` 里的值」，「名称」注明**它只是个标签**。
另外：**认证失败时会明确提示去勾上「允许在终端里输入密码」** ——
不勾那项时密码登录根本不会问你（以前用户只看到"失败"，不知道差在哪一步）。

## 4. 报错中文化：中文短句 + 原文，别再让用户猜

以前 russh 的英文报错被原样透到界面上，例如
`No common Kex algorithm - ours: […], theirs: […]` ——
中文提示里冒出一个**孤零零的 `-`**，用户第一反应是"你们参数拼错了吧"（这就是那次报障的由来）。

现在收敛成「**中文短句｜原始信息：英文**」：中文部分直接显示（算法不匹配 / 认证失败 /
连不上服务器 / 连接失败四类），**英文原文一律留在后面**（状态栏那行只显示中文那半，全文进悬停），
排查时不用翻日志。SFTP 连接（含跳板机的两条路）也走同一套。
顺带清掉了远端提示里所有孤立的 ` - ` 破折号（改成句号断句）——
这类"看起来像 bug 的排版"也是同一类成本。

## 5. 本机 AI CLI：起不来能认出来，还能一键修

以前"装了 codex 但起不来"在界面上没有任何表现，用户只能自己去终端里试。
现在本机 CLI **装了没 / 装了但坏了 / 正在自更新** 三种情况会被认出来：

- **判据只写一份**（后端 `src-tauri/src/core/cli_health.rs`）：`where` 找入口、
  **外加**自己查 npm 全局 bin 目录的候选入口 ——
  只查 `where` 会把"包在、`codex.cmd` shim 丢了"误判成"没装"；
  候选顺序按 Windows 能直接起的优先（`.cmd` > `.exe` > `.ps1`，无扩展名的 sh 脚本排最后，
  否则会把好的 codex 误报成坏的）。认不出来就写 `Unknown`，**不猜**；
- **异常出现在两处**：看板的承载健康位 + **状态栏那一行**（面板没开着也能看见，点一下跳到那一块）；
- **一键修**：重装命令由后端按**固定白名单**拼（codex / claude / gemini / aider），
  **执行前把命令原文给你确认**（`confirm=false` 时只回"将要执行什么"，一个进程都不起；
  确认框里显示的就是**真正会跑的那一条**，不是前端自己拼的近似文案）；
  **失败可见**（stdout/stderr 摘要 + 退出码一起回显，跑满 10 分钟会告诉你"可能还在后台装"）；
  **绝不静默安装**。aider 是 Python 生态（`pip` 会按环境挑解释器、可能装进系统 Python），
  所以我们**不代跑**，只把命令原文给你自己粘。
- **`--no-daemon`**：codex 的"守护进程起不来（`os error 5`）"官方建议加这个参数。
  我们**不去改你的全局配置**（那会影响你所有终端里的用法），只记住
  "**我们自己**启动它时多带一个参数"（`settings.agent_launch_args`，值是**白名单**里的参数，
  因为它最终要被拼进一条要敲进终端的命令）；界面上也照这句话说清楚。

## 6. 盖碗图标 + 一条构建教训

应用图标换成了盖碗（`tauri icon` 生成整套 7 个文件：ico / icns / 各尺寸 png）。

**教训**：换完图标重新构建，exe 里可能**还是旧图标** —— 构建缓存让资源没被重新嵌入。
判断的土办法是直接看构建产物；靠谱的做法是**改图标后先
`cargo clean -p zeeai-terminal --release` 再构建**。这条已经写进 `AGENTS.md`，
免得下次又对着一个"明明换了却没变"的 exe 怀疑人生。

## 7. 其它修复

- **本地会话"正文/回车被 ConPTY 合成一次"导致不提交**：从 AI 输入窗发一条消息时，
  正文与回车是两次写入，但**本地 ConPTY 会把它们合成同一次 read** ——
  用一个"假 TUI"实测，本地只看到 **1 段**（`\x1b[200~正文\x1b[201~\r`），
  而走 ssh 的远程会话是分开到达的。同一条消息"喂给程序的样子"不一样，
  正是"远程正常、本地不提交"这类怪事最喜欢藏的地方。
  现在**回车隔 40ms 单独写**（对普通 shell 毫无影响），并用一条**串行链**保证
  "上一条的回车"永远排在下一条的正文前面 —— 否则连发两条时第 2 条的正文会插到第 1 条的回车前。
- **终端报错分流**：连接类报错进状态栏那一行时只显示中文短句，英文原文进悬停
  （和上面第 4 条配套）。

## 已知限制 / 这次没做的

- **红点的"轮次"是按"最后一次证据的时间"去重的**：如果某个 agent 在**同一秒内**跑完两轮，
  理论上只算一轮、只亮一次。这种情况我们没有真机复现过；
- **裸 SSH 的「需要你」仍然拿不到**：进程扫描只能看到"有这么个进程"。
  行业正在跟进的 **OSC 7501**（由 agent 自己上报状态）能解决它，
  我们这一版**按计划不动**（不加 handler、不在界面上留占位）——
  等 codex / claude 发布支持它的版本再接入，那时裸 SSH 会从"永不显示"升级成"有自报才显示"；
- **本机进程扫描认不出承载是 CMD 还是 PowerShell**（只按进程名过滤），
  所以本机一律按 PowerShell 处理 —— 这只影响卡片上的徽标文案，不影响状态闸门
  （两者都不许说"需要你"，也不给裸 SSH / CMD 下"已完成"的结论）；
- **rollout 快照只有 codex 会写**，所以那条来源只能填 codex；它里面也没有窗格/pid，
  只能靠"环境 + agent + 目录"去认领一个已有实例，认不到就单独成卡（卡上标"仅日志"）；
- **一键修只代跑 npm 生态的三个**（codex / claude / gemini），且只支持重装这一种修法；
  `--no-daemon` 也只影响"从我们这里启动"的方式，**你在别的终端里的用法不变**；
- **启动耗时的数字来自本机实测**（探针脚本在仓库里，可复现）——
  不同机器、不同杀软/首启冷缓存下会有出入；我们改的是"重活等首帧"，不是承诺一个毫秒数；
- 这一版**没有**做：看板的历史/统计页（时间线只在折叠行里）、OSC 7501 接入、
  远端 CLI 的健康检查（`cli_health` 只管**本机**）。
