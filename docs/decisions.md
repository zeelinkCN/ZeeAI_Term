## 第九轮更新 · ① 凭据管理器 + ② 工作区恢复（队列前两项完成）

### ① Windows 凭据管理器：密码登录的服务器现在能干活了

以前用密码登录的服务器：终端能连（ssh 自己弹提示），但**远程文件、tmux 列表全都不行**——
一次性命令走 `BatchMode=yes`，而系统 ssh **没法从命令行喂密码**。

现在：

- 密码存在 **Windows 凭据管理器**（`keyring` crate），**不写进 profiles.json**；
  服务名 `ZeeAI-Terminal`，在「控制面板 → 凭据管理器 → Windows 凭据」里能看到、也能自己删；
- 服务器编辑对话框新增 **密码输入框 + 保存密码 / 清除密码**，并显示"✓ 已保存密码"；
- 取到密码后：
  - **SFTP**（列目录 / 读文件 / 上传 / 下载 / 新建 / 改名 / 删除）用密码认证；
  - **一次性命令**（tmux 列表、pane 当前目录）改用 **russh 直接 exec**，绕开系统 ssh 的限制；
    没配密码时仍走系统 ssh（更快、复用 known_hosts）。

真机验证（在测试服务器上临时建了密码账号 `pwuser`，`cargo run --example secret_probe`）：

```
1) 写凭据管理器 …         has_password = true
2) 用密码建 SFTP 连接 …   OK: 家目录 /home/pwuser，4 项
3) 读一个文件 …           OK: hello from password user
4) 借这条连接 exec 命令 … OK: pwuser | /home/pwuser
5) 删除凭据 …             has_password = false
```

## 第七轮更新 · 真 SFTP + 目录跟随（含非 tmux）+ Git 面板能干活了

### 1. 文件传输从 scp 换成**真正的 SFTP**

原来用系统 `scp`，被你说"不是真的 SFTP"——确实：scp 走的是老 SCP 协议，远端路径要被远端
shell 解释，空格/特殊字符靠引号硬凑（还踩过 `filename does not match request` 的坑）。

现在换成纯 Rust 的 **russh + russh-sftp**（`src-tauri/src/core/sftp.rs`），标准 SSH_FXP 协议，
路径是**字面量**、不经过 shell：

| 能力 | 说明 |
|---|---|
| 列目录 / 读文件 | `fs_list` / `fs_read` 走 SFTP |
| 上传 / 下载 | 支持文件与目录（目录递归），返回传输字节数 |
| 新建目录 / 重命名 / 删除 | 全部走 SFTP（删除目录会递归） |
| 认证 | 先试密码（为凭据管理器预留）、再依次试配置密钥 → `~/.ssh/id_ed25519` → `id_rsa` → `id_ecdsa` |

顺带加了 `cargo run --example sftp_spike -- <host> <user>` 这个探针，能单独验证 SFTP 链路。

实测（内置自检）：

```
fs_upload  ok -> 已上传 1 项（24 B）到 /tmp/zeeai-selftest
fs_list    ok -> 1 entries at /tmp/zeeai-selftest
fs_download ok -> 已下载 1 项（24 B），roundtrip match = true
fs_rename / fs_remove ok
```

> 说明：**进度条还没做**（第⑤项）。但 SFTP 是按 64KB 分块读写的，加进度条的底座已经有了。

### 2. 非 tmux 会话也能跟随工作目录了（OSC 7）

之前只有 tmux 会话能拿到实时目录（靠 `tmux display-message -p '#{pane_current_path}'`），
普通 shell 拿不到。现在：

- 启动普通 shell 时，远端命令会先注入一段 `PROMPT_COMMAND`，让 bash **每次画提示符时**
  输出 OSC 7 序列（`ESC ] 7 ; file://主机/路径`）——**不改服务器上任何文件**，靠环境变量传入；
- 前端 xterm 解析 OSC 7，记进会话的 `cwd`；
- 文件面板新增 **「⤓ 同步终端目录」** 按钮：点一下直接跳到终端当前所在目录。
  tmux 会话走 tmux 查询，普通 shell 走 OSC 7，两条路都通；
- 「刷新」按钮的语义改回"重读当前目录"，避免它自作主张跳走。

实测（服务器上直接验证）：`^[]7;file://my-server/tmp^[\` —— bash 确实上报了。

### 3. Git 面板从"只读"变成能干活

- **新建仓库**：`git init -b main`（目录不存在会自动创建），建完直接开终端；
- **打开本地仓库** → 存成工作空间 → 在该目录开本地终端；工作空间行有「新终端」按钮，
  想开几个开几个；
- **更改 / 已暂存** 两组文件列表（VS Code 那种分法），行内按钮：
  `＋` 暂存、`−` 取消暂存、`↺` 丢弃改动（丢弃有二次确认）；
- **提交**：提交信息框（Ctrl+Enter）+ 提交按钮，提交完自动刷新；
- **提交历史**：最近 30 条，点一条看完整 diff；
- **分支**：列出本地分支（含上游和最近提交时间），点一下切换，也能"新建并切换"；
- **看 diff**：点文件行打开 diff 弹窗，`+`/`-` 行有配色。

### 4. 本地终端模块能看到"我已经开了几个"

PowerShell / CMD / WSL 的侧栏现在会列出**这个模块已经打开的会话**：

```
已打开的 POWERSHELL (2)
  > ZeeAI_term · git     ●
  > PowerShell           ●
```

点一下切换、× 关闭；同一模块开多个会自动编号（PowerShell、PowerShell 2…），
不用再跑到顶部标签栏一个个找。

### 5. 服务器列表交互按你说的改了

- **默认展开**（新加的服务器也是展开的）；
- **单击服务器名** = 展开 / 收起它的会话历史；
- **双击**或**右键** = 打开服务器设置（编辑 / 复制 / 删除 / 管理 tmux）。

### 6. 顺带修的小问题

自动演示模式每跑一次会往配置里塞一条重复的工作空间/串口记录，已加去重，
并把已经产生的重复条目清理掉了（你的配置现在是 4 条：测试服务器、lz、Git 工作空间、COM5）。

## 第五轮更新 · 文件上传/下载（M3）+ 真机串口验证（最新）

### 1. 远程文件现在能双向搬了（以前只能看）

- 文件面板工具栏新增 **上传** 和 **新建文件夹**；
- 每个文件/目录行上新增 **⋯** 按钮，也可以直接**右键**，菜单里是：
  **打开预览 / 下载到本机… / 重命名… / 删除**（删除会先弹确认，不可撤销的操作不直接执行）；
- 上传支持**多选文件**，选中的**文件夹会整个递归上传**；下载目录同理（内部先问一次远端是文件还是目录，
  再决定要不要 `-r`）；
- 底层用系统 `scp`（和 ssh 同一套密钥/agent），不再自己拼 shell；
- 途中踩到一个坑记一下：Windows 自带的是 OpenSSH **8.1**，`scp` 走的是**老 SCP 协议**，
  远端路径会被远端 shell 解释。我们为了支持带空格的路径会给路径加单引号，结果本地 scp 会拿这串
  字面量去比对远端回传的文件名，直接报 `protocol error: filename does not match request`。
  解决：加 `-T` 关掉这个比对，带空格的路径也能正常上传/下载（已实测 `b b.txt` 这种名字）。

### 2. 你接在 COM5 上的设备，我拿去真跑了

COM5 上是一块 **ESP32-S3**（CH343 USB 转串口，驱动 wch.cn 2.1.2025.7），跑着 `led_strip` 示例。

过程中发现一件事，**值得你知道**：一开始 COM5 是**打不开**的，
`mode COM5:` 和 .NET 串口都报 *「设备无法正常工作 / 该设备不支持这些设置」*，
但设备管理器里状态显示是正常的。我用 `pnputil /restart-device`（管理员）**重启了一次这个 USB 设备**，
之后 115200 就能正常收数据了。所以以后遇到「串口在设备管理器里看着好好的、但程序打不开」，
先拔插一次 / 重启这个设备，别怀疑软件。

真机验证结果（走的是应用自己的串口代码路径，不是我另写的脚本）：

```
SELFTEST: serial_list ok -> 3 ports
SELFTEST: serial_probe COM5 (USB-Enhanced-SERIAL CH343 (COM5) · wch.cn) ok
          -> 288 bytes | I (104888) example: log -> UART ... example: print -> stdout
```

界面里也验证过了：点 COM5 会开出一个 `串口 · COM5 · 115200` 的终端标签，实时刷出板子的日志。
另外两块是蓝牙虚拟串口（COM3/COM4），现在侧栏会标注「串口（未识别型号，可能是蓝牙或虚拟串口）」，
免得你误点——蓝牙口打不开是正常的。

## 第四轮更新 · 服务器管理 + 用普通用户登录（最新，先看这个）

这一轮就是回答你那两个问题：**「服务器新增/管理不完善」** 和 **「想用普通用户登录，为什么不能选用户」**。

### 1. 服务器管理现在是一条完整的链路

- 侧栏「已保存的服务器」标题右侧有两个按钮：**＋（新建服务器）** 和 **⋯（服务器管理）**。
- 新增独立的**服务器管理**窗口（顶部菜单 `连接 → 服务器管理…`）。每一行显示
  `用户名@主机:端口 · 分组 · 认证方式`，右侧四个动作：**新建会话 / 编辑 / 复制 / 删除**
  （删除是两步：点「删除」后要再点一次「确认删除」，避免手滑）。
- 在服务器行上**右键**的菜单也保留了：新建会话 / 编辑服务器… / 复制服务器 / 管理 tmux 会话 / 删除服务器。
- 「新建会话」弹窗里的服务器下拉框下面有三个按钮：**＋ 新建服务器 / 编辑当前服务器 / 服务器管理**。
  从弹窗里点「＋ 新建服务器」，保存后会**自动回到新建会话弹窗并选中刚建的这台**，不用再找一遍。

### 2. 登录用户：现在可以随便选，而且真的按你选的用户走

- 「新建会话」弹窗里新增了 **登录用户** 输入框（默认填服务器配置里的用户名）。想用普通用户登录，
  直接把 `root` 改成 `你的用户名` 就行，**不用改服务器配置、不用新建一条配置**。
- 下面有开关「**把这个用户名保存到该服务器的配置里**」，勾上就写回配置，下次默认用它。
- tmux 会话名跟着用户名走（默认模板 `{host}-{user}`）。所以同一台机器上 root 和普通用户
  用的是**各自独立的 tmux 会话**，不会两个人抢同一个会话把窗口挤成「满屏点点」。
- **顺带修掉一个真 bug**：远程文件浏览 / tmux 列表以前永远按**配置里的**用户名去连，
  所以哪怕你用普通用户登进去了，侧栏文件还在按 root 的权限和家目录读——完全对不上。
  现在这些操作都跟着**当前会话实际登录的用户**走（重连、再打开也一样）。
- 服务器配置里新增「**允许在终端里输入密码**」（默认关）。关着的时候走 `BatchMode=yes`，
  只用密钥/agent，连不上会直接报错，不会卡在密码提示上；打开了就允许 ssh 在终端里问你要密码。

> 注意：远程文件/tmux 这类「一次性 ssh 命令」目前只支持密钥或 ssh-agent 登录。
> 如果你的某个服务器只能用密码，终端能连上，但侧栏文件会报错——这条记在 B 节待你拍板。

### 3. 顺带做完的（原计划 M4/M5）

- **Git 面板**：填本地仓库路径 → 显示分支、上游、领先/落后、改动文件列表（左侧栏 Git 图标）。

## A. 我替你做的决定

### A1. SSH 先用「系统 OpenSSH 客户端 + PTY」，不是原生 russh

设计文档里写的是用 `russh` 自己实现 SSH 客户端。今晚我改成 **把系统自带的 `ssh.exe` 跑在 PTY 里**（也就是让 `ssh` 自己去处理认证、known_hosts、agent）。

原因：

1. 你本机已经配好免密，用系统 `ssh` 能直接复用你的 `~/.ssh/config`、密钥和 agent，零配置就能连上，可靠性最高。
2. 今晚的目标是「能用的版本」，原生 russh 需要自己实现认证握手、密钥解析、PTY 请求等，风险和时间都更高。
3. tmux 持久化用这种方式非常自然：直接执行 `ssh -tt ... "tmux new-session -A -s <名字>"`。

**代价 / 什么时候必须换回 russh**：做 SFTP 文件窗格（M3）时，需要一个能编程调用 SFTP 子系统的客户端，届时会引入 `russh`（或 `ssh2`）并保留现在这条作为「兜底/兼容」路径。

**如果你更希望一开始就走原生 russh，请告诉我，我改。**

### A2. 终端数据用 base64 走 Tauri Channel

后端把 PTY 原始字节按 base64 编码后推给前端，前端解码成 `Uint8Array` 喂给 xterm.js。

原因：直接传字符串会在 UTF-8 多字节字符被拆包时出现乱码；base64 保证字节级正确。代价是约 33% 传输开销。**后续优化项**：若能确认 Tauri Channel 支持裸二进制载荷，再改成零拷贝。

### A3. 打包只做 NSIS 安装包

`tauri.conf.json` 里 bundle target 从 `"all"` 收成 `["nsis"]`，避免 MSI(WiX) 那条链路的额外下载和失败面。如果你需要 MSI，我再加。

### A4. 首次运行内置一条「测试服务器」记录

首次启动时会在配置里写入一条 SSH 记录：名字「测试服务器」，`root@203.0.113.10:22`，开启 tmux。目的是让你一打开就能点着试用，不用先手动建连接。**它是普通记录，可以在侧栏删掉。**

### A5. 主机密钥策略用 `accept-new`

首次连接陌生主机时自动接受并写入 `known_hosts`（等价于第一次 `ssh` 时的 yes），避免在无交互环境下卡在确认提示。这是「能用」与「安全」之间的折中，**请你确认是否接受**；若你要求严格校验，我改成弹窗确认。

### A6. 暂缓的功能

今晚聚焦「能跑起来、能连服务器、能开本地终端」。以下按设计文档留到后续里程碑，界面上先留了占位提示，不会假装已实现：

### C1. 修复了 VS 安装器的两个注册表值

### C2. 新增了 cargo 全局镜像配置

新建 `C:\Users\m1523\.cargo\config.toml`：把 crates.io 指向 `rsproxy.cn` 稀疏索引，并关闭 HTTP 多路复用。

### C5. 在你的测试服务器上安装了 tmux

`203.0.113.10` 原本**没有 tmux**（`tmux: command not found`），而 tmux 持久化是本产品的核心功能，没它就验证不了。我用 `dnf install -y tmux` 装上了 **tmux 2.7**（Anolis / Alibaba Cloud Linux 3 官方仓库版本）。


### C6. 在你的测试服务器上新建了普通用户 `zeeai`（今晚新增）

为了验证「用普通用户登录」这条路（以及修掉的那个「文件浏览不跟着登录用户走」的 bug），
我在 `203.0.113.10` 上建了一个测试账号：

```bash
useradd -m -s /bin/bash zeeai
mkdir -p /home/zeeai/.ssh
cp /root/.ssh/authorized_keys /home/zeeai/.ssh/authorized_keys
chown -R zeeai:zeeai /home/zeeai/.ssh && chmod 700 /home/zeeai/.ssh && chmod 600 /home/zeeai/.ssh/authorized_keys
```

它**不在 sudo 组**，权限等价于一个普通登录用户；用的还是你原来那把钥匙，
所以你本机不用做任何额外配置就能 `zeeai@203.0.113.10` 直接登。

回退：`userdel -r zeeai`。

另外，代码里已经加了**检测与降级**：以后连到没装 tmux 的服务器，会自动退回普通 shell 并在终端里打印安装提示，不会再直接报错。
