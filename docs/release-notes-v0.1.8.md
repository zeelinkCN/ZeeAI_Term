# ZeeAI_Term v0.1.8

这一版**没有堆新功能**，主题是「把地基修稳 + 把包做小」：
**一键升级的致命 bug 修掉了**、安装包和便携版**体积几乎减半**，另外补了一批
"平时不炸但会一直消耗体验"的问题（会话卡死、配置被悄悄重置、日志难读、通知漏报的隐患）。

> ⚠️ **升级方式（重要）**：如果你现在装的是 0.1.7，**请手动装这一版**
> （下载下面的安装包双击，或解压便携版）。
> 原因：坏掉的是 **0.1.7 自己**的升级逻辑——它会在启动安装程序的那一刻把自己的升级脚本杀掉，
> 所以从 0.1.7 点"一键升级"仍然不会有反应。**从 0.1.8 开始，一键升级才是好的。**

---

## 1. 升级链路：修掉"点了升级什么都没发生"

这是 0.1.5 那次事故的真身，也是 0.1.6 / 0.1.7 一直没解决的根因：

**升级辅助脚本被挂进了「App 一退就杀掉所有进程」的 Job Object，而它要做的第一件事恰恰是"等 App 退出"。**
两边一撞，脚本恰好在它唯一需要活下去的那一刻被系统杀掉 → 安装器永远不会运行 →
`apply_update.log` 也不会写 → 你看到的就是"应用关了、版本没变、也没有任何提示"。

这一版把这几件事一起修了：

| 修了什么 | 说明 |
|---|---|
| **脚本不再被连带杀掉** | 升级脚本不再挂 Job Object（curl 和终端子进程继续挂，它们才怕变孤儿） |
| **MSI 也会自动重启** | `msiexec` 补上 `AUTOLAUNCHAPP=1`。以前 MSI 用户升完就是"应用没了"，得自己去开始菜单点 |
| **装完必定把应用拉起来** | 兜底：装完等约 10 秒还看不到进程，脚本自己 `start` 一次 |
| **升级包不再堆积** | 以前只有失败才删包，升一次就在 `%TEMP%` 留一份 9~14MB；现在成功也删，下次下载还会顺手清掉旧版本的残留 |
| **弱网不再从头重下** | 支持真断点续传（`curl -C -`）：代理续传 → 直连续传 → 从 0 重来，三级策略。**只有网络层失败才保留半截文件**，校验不过一律丢弃 |

安全上还收紧了一道（你自己要求过"**下载的时候不要下错**"）：
自动下载**只允许本项目自己的 Release 地址**，而且**必须带官方文件大小**——
以前大小和 sha256 都由界面传入，传空时唯一剩下的检查是"文件头是不是 MZ"。

## 2. 体积：安装包和便携版都小了一半左右

| 产物 | v0.1.7 | **v0.1.8** | 变化 |
|---|---|---|---|
| 免安装 exe | 16.63 MB | **8.43 MB** | **−49%** |
| NSIS 安装包 | 9.15 MB | **6.32 MB** | **−31%** |
| MSI 安装包 | 14.08 MB | **9.49 MB** | **−33%** |
| 便携版 zip | 13.48 MB | **8.89 MB** | **−34%** |

怎么做到的（都不碰任何功能）：

- **删掉 platform-tools 里代码从未引用的二进制**：`sqlite3.exe`（3.03MB）、`mke2fs`、
  `make_f2fs`×2、`etc1tool`、`hprof-conv`、`libwinpthread-1.dll` 等。
  删之前先在隔离目录里验证过"只留 adb + 两个 dll + fastboot 也能正常跑"，
  打包后又在便携版里跑了一遍 `adb version` / `fastboot --version` 做回归。
- **开启发布构建优化**：`lto` / `codegen-units=1` / `strip` / `panic=abort`（以前一个都没开）。
- 删掉 Windows 用不到的 `icon.icns` 与 `Square*Logo`。

## 3. 稳定性：三个"平时不炸但迟早咬人"的问题

**① 一个卡住的会话能拖死整个应用。**
`session_write` / `session_resize` / `session_close` 以前都是**握着全局会话表锁**去做写/杀进程。
只要有一个会话的远端不再回显（管道写满），那个阻塞写就会一直占着全局锁 ——
于是所有会话操作一起排队，**连你想关掉那个卡住的会话都点不动**，只能杀进程。
现在改成"锁里只取句柄，出锁再做 IO"。

**② 配置被悄悄重置成默认值。**
设置 / 服务器列表 / 工作区以前是直接覆盖写，升级安装撞上写盘窗口就会留下半截 JSON，
下次启动解析失败 → 静默回落默认值 —— 用户看到的就是"**服务器列表突然空了**"。
现在改成"写临时文件 → 原子改名"，解析失败时还会先把坏文件备份成 `.bad-<时间戳>` 再回落。

**③ 远端探测没有超时。**
系统 ssh 没配连接超时，一旦挂住，AI 看板的刷新守卫就永远松不下来，**看板从此不再刷新**。
现在整条远端命令链路有 20 秒上限。

## 4. 会话日志与终端体验

- **进度输出终于能读了**：`docker pull` / `curl` / `npm install` 这类靠 `\r` 原地刷新的输出，
  以前 CR 被直接丢掉，整个进度会被拼成**一条读不了的长行**；现在会正确断成多行
  （`\r\n` 仍然只算一个换行）。
- **开日志不再拖慢终端**：以前每收到一片 PTY 输出就落盘一次，`tail -f` 那种高频输出会变成
  每秒上千次写盘 + Defender 实时扫描；现在攒够 64KB 或 200ms 才落一次（正常退出仍会收尾）。

## 5. 修复与小改进

- **同一个 tmux 会话不再被打开两个客户端**：以前"tmux 管理面板点连接"和
  "新建会话 → tmux 新建 → 名字留空"这两条路会重复挂同一个会话。
  老版本 tmux 在多方 attach 时**按最小的客户端算窗口尺寸**，会把画面挤变形、把历史压坏
  （详细机制见 `docs/review/bug-tmux-scrollback-narrow.md`）。现在所有入口统一去重，已开着就直接切过去。
- **高亮引擎两处边界**：颜色恢复状态不再失真；跨分片的整词匹配不再把 `PIN**OK**ED` 里的 `OK` 误判成独立单词。
- **修掉标签标题的三元运算符优先级 bug**（`a || b ? x : y` 在 JS 里等价于 `(a || b) ? x : y`）。
- **改设置不再互相覆盖**：同一次操作里连着改两项设置，前一项不会被后一项用旧值盖掉。
- 侧栏宽度这种本地存储读写加上了异常兜底。
- 「关于」页不再硬编码版本号。
- 新增 `scripts/build-portable.ps1`：便携版打包从"手工四步"变成一条命令（自动打印 sha256）。
- 新增 4 个单元测试（原子写、升级目录清理、Release 白名单、CR 断行）。

## 6. 验证情况（说清楚验证了什么、没验证什么）

**验证过**

- `cargo test --lib`：**55 通过 / 0 失败**（比上版多 4 个）。
- `npx tsc --noEmit`：0 错误。
- `npm run tauri build`：成功产出 exe + NSIS + MSI。
- 便携版冒烟：启动正常，日志里能看到它真的跑完启动链路
  （读配置 → 恢复工作区 → 连上 SSH → `remote_pwd` → 列目录 20 项）。
- adb / fastboot 在**打包后的便携版目录**里回归通过。

**没验证（如实说明）**

- **没有做一次真实的一键升级**：这需要"包含修复的新版本"作为升级目标，也就是要等这一版发出去之后，
  从 0.1.8 升到 0.1.9 时才能真跑一遍。所以这一版请**手动安装**。
- 删减 platform-tools 后没有接真实安卓设备测 ADB 文件管理（只验证了 adb/fastboot 可执行）。
- `needs-approval`（"等你批准"）状态仍然没有真实样本（本机所有会话都是 `approval_policy = never`）。
