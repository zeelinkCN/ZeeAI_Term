## 1. 稳（技术文档 T-12 / T-14）

### T-12：AI 探针不再"截最后 40 万字节"

**问题**：实测某条会话最后一次 `task_complete` 距文件尾已有 **293KB**，窗口一旦被一轮大输出撑爆，
"AI 跑完了 / 等你批准"就**静默失效**（正是用户反复问的"为什么没提示我去看那个 Markdown"）。

**改法**：不再按字节截，改成**按记录类型各取最后几条**：

- 远端：`tail -c 4MB | awk '<分桶取尾>' | sort -n`（分桶规则与本机同一套）；
- 本机：同样规则在 Rust 里实现（`select_related`）。

**实测收益**：真服务器上同一条会话，回传从固定 **400KB → 约 16KB**，而且
被 1.5MB 噪声埋在中间的 `task_complete` 也能读到（新增单测
`finds_completion_even_when_buried_under_noise` 覆盖这个场景）。

**踩到并修掉一个真坑**：这个仓库的源码是 CRLF，而 Rust 的**原始字符串**会把行尾 `\r`
一起带进程序文本 —— 多行 awk 传到远端直接语法错误。改成单行 awk 解决，
并且用 scp 把生成的脚本原样送到真服务器上跑通验证（测完已删 `/tmp` 上的脚本）。

### T-14：本机进程扫描更省

原来是每 20 秒起一个 PowerShell 枚举**全进程表**。现在：

- PowerShell 查询加 `Name` 白名单（只查可能相关的可执行名）；
- 前端给本机扫描单独限流到 **60 秒一次**（远端探针不受影响）。

## 2. G-01：AI 任务时间线（落盘）

**为什么**：看板只显示"当前这一轮"，而 `AiTaskRegistry` 是内存里的，应用一关就全没了 ——
用户要的"我离开电脑再回来，昨晚跑了什么"根本查不到。

**做了什么**：

- 新增 `src-tauri/src/core/ai_history.rs`：把每一轮完成的事实落盘到
  `%APPDATA%\ZeeAI-Terminal\ai_turns.json`（**原子写**、按 `env|server|会话|完成时间` 去重、
  上限 300 条、后到的字段可以补进已有记录）；
- 新增三个命令 `ai_timeline_list` / `ai_timeline_add` / `ai_timeline_clear`；
- 前端在"发现新一轮完成"那一刻（`considerSnapshot` 的 `freshTurn` 分支）记一条 ——
  那里刚好手上有全部信息（服务器、项目目录、AI 最后一段话、耗时、这一轮的产物）；
- AI 面板新增「最近任务」列表：时间 / 服务器 / 项目 / 耗时 / 消息摘要 / 产物标签，
  最多显示 40 条，可刷新、可一键清空（只删记录，不动会话和文件）。

**注意**：不管最后提不提醒（比如你正盯着那个终端看），都会记一条 —— 记录和打扰是两件事。

## 3. G-02：shell 集成（OSC 133）—— 做了一半，如实说明

**做了什么**：

- shell 集成里加发 OSC 133 的 `D;<退出码>`（注入方式仍是 `PROMPT_COMMAND`，
  和当初做 OSC 7 完全同一套：**不修改服务器上任何 rc 文件**）；
- 终端注册 `registerOscHandler(133)` 捕获它，卡片上显示「最近一条命令退出码 N（成功/失败）」。

**没做到的部分（诚实记录）**：

- **tmux 会话拿不到这个信号**。tmux 里 shell 的环境来自 tmux server，而 server 可能是别的
  客户端先起的；这台服务器 tmux 还是 **2.7**，没有 `-e` 传环境变量，而模拟按键做 tmux 操作
  是被明确禁止的。所以"AI 在 tmux 里跑"这条主路径上，退出码仍然拿不到。
- 因此 G-02 的另一半（**产物清单精确到命令级**）本轮没完成。当前产物仍然靠
  "会话 cwd + 这一轮的时间窗"推断。要真正做成，需要先把 tmux 升到 ≥3.2（用 `-e` 传环境）
  或者换一种不依赖 shell 的采集方式 —— 这属于需要用户拍板的改动。
