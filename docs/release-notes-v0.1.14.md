# ZeeAI_Term v0.1.14

> **替代发版**：本版是 v0.1.14 的**替代发版** —— 版本号不变（仍是 0.1.14），基于最新代码重新构建；此前发布的 0.1.14 构建作废，请以本次 Release 的产物为准。

这一版的主题是**"把 SSH 报障一次收干净，把输出链路的账还上"**。两件事本来不相干，但都指向同一个问题：用户遇到麻烦时，我们给的信息不够，或者给得太慢。

1. **SSH 连不上时，界面只给一句英文原文**（中间还夹着孤立的 ` - `），用户只能猜；密码模式把本机现成的免密配置绕过去了，也没人告诉他；
2. **"终端越用越卡"**：PTY 每 read 一片就 base64 一次、发一次 IPC，没有合并、没有背压 —— 30 万行输出就是 30 万次 IPC。

这一版把两件事一起处理：SSH 的所有错误出口统一成「**中文分类｜原始信息：英文**」，新增只读的「连接诊断」（两处入口，直接告诉你 `ssh -G` 实际会用什么登录）；反过来，输出链路加了 **16ms / 64KB 合并** + **seq ack 真背压**，同一份 18.2MB 的大输出，IPC 次数从 30 万降到 1.4 万。

顺带补上安全审查挑出来的几个洞（主机密钥 TOFU、配置/历史原子写、ADB 与"打开链接"的注入面、多字节截断、tmux 引号），并处理三条用户直接提的交互问题（输入框按会话独立、tmux 里拖不出选区、会话标签看不出承载方式）。**AI 面板按用户要求暂停用**：点开只有一块灰色空容器，内容一条都不渲染。

## 1. SSH 报错全线收口：中文分类｜原始信息

**改了什么**：把 `ssh.rs` 里原来那个只分四类的 `friendly_ssh_error` 拆成两个函数，再补一个"带动作上下文"的入口：

- `classify_ssh_error(raw, fallback)` —— 分类扩到 6 类、外加一个按动作兜底的默认档：算法不匹配 / 主机密钥校验失败（密钥变了）/ 认证失败 / 权限不足 / 路径或文件不存在 / 连不上服务器；
- `sanitize_raw(raw)` —— 原始信息里的 `" - "` 换成全角冒号、CRLF 归一、空串写成「（没有更多信息）」；
- `friendly_ssh_error_context(context, raw)` —— 输出 `动作：分类｜原始信息：…`，给 SFTP / scp / 跳板机 / herdr 这些"只知道动作"的出口用。

**为什么**：用户报障截图里的原文是 `No common Kex algorithm - ours: […], theirs: […]` —— 中文提示里冒出一个孤零零的 `-`，他以为是我们打错了字。更根本的问题是**英文原文被原样透给界面**：没有分类，用户不知道该改 key、改密码还是改网络。

**怎么验的**：

- 单测 `six_common_ssh_errors_are_friendly_and_have_no_stray_dash`：喂 6 条真实英文报错（Kex 算法、Authentication failed、Permission denied (publickey)、Connection refused、timed out、Host key verification failed），逐条断言 ① 分类是中文 ② 保留「｜原始信息：」 ③ **整条字符串不含 `" - "`**；
- 单测 `herdr_error_events_are_classified_without_stray_dash`：herdr 的 stderr 是原样进事件流再进状态栏的（绕过了分类），现在在 `commands.rs` 这一层统一改写，并断言 `Data` 事件**不许**被改动；
- 覆盖到的出口：russh 连接 / 跳板机转发 / 跳板机再连目标、scp、一次性远端命令、herdr 观察流、herdr 输入通道、herdr 窗格 resize、打开 SSH 终端、打开 herdr 观察流。

## 2. 新增「连接诊断」：只读跑一次 `ssh -G`

**改了什么**：

- 后端 `core::ssh::diagnose()` + 新命令 `ssh_diagnose`：只解析本机配置，**不连接服务器**、不写任何文件；10 秒超时，进程走 `hidden_command_async`（不闪黑窗）；系统没装 OpenSSH 客户端时给一句明确中文；
- 返回三样东西：`effective`（实际生效的 hostname / port / user / 多个 IdentityFile / ProxyJump / ProxyCommand / IdentitiesOnly / BatchMode）、`key_files`（每个候选密钥 + 是否存在）、`summary`（一句人话）；
- 前端 `SshDiagnosisModal` + **两处入口**：①「编辑服务器」里的「连接诊断」按钮；② 连接失败提示里的「为什么会失败？诊断一下」；
- 弹窗只展示人看得懂的东西：一句大字总结、实际生效的主机/端口/用户、每个密钥的 ✓/✗、有才显示的跳板机 / ProxyCommand / IdentitiesOnly / BatchMode，以及前端算的第二句人话结论（分"能连 / 要留意 / 会失败"三档色条）。**不摆原始 JSON**。

**为什么**：用户说"连不上"时，我们过去只有两条路 —— 让他自己去看 `~/.ssh/config`，或者让他把配置发过来。而真正决定"你会怎么登录"的是 `ssh -G` 的合并结果（别名展开、`Match` 块、系统默认密钥、agent 配置都会参与），人眼很难推。把它摊开，用户自己就能看出"我填的私钥根本不存在"或者"这台机器其实会用另一把钥匙"。

**怎么验的**：

- 单测 4 条（都喂固定文本，不联网）：`ssh -G` 多 IdentityFile 提取与 `none` 归一；留空的端口/用户/密钥不传参（否则会把 config 里的值顶掉）；密钥存在性与 summary 文案；`~/.ssh/xxx` 与展开后的绝对路径必须认成同一个文件（不重复列出）；
- 无头断言 9 条：两处入口、端口/用户显示、✓/✗ 标记、有跳板机才显示跳板机、人话结论、界面上没有原始 JSON、遮罩 / ✕ / 「关闭」三种关闭方式。

## 3. 密码模式提示：别让"免密配置"被一个勾选框白费

**改了什么**：后端新增 `PASSWORD_MODE_HINT` 常量和 `password_mode_hint()`；前端在诊断弹窗里给一条琥珀色提示。文案是：

> 本机已有免密配置；密码模式不会使用 ~/.ssh/config 与 ssh-agent，若想免密请取消勾选「允许在终端里输入密码」

**为什么**：勾了「允许在终端里输入密码」之后，终端那条路会走密码登录。本机明明配好了密钥和 agent，却因为一个默认勾选被绕过 —— 用户看到的是"认证失败"，完全想不到是那个勾。

**口径（两处刻意收窄）**：

- 后端只在「启用了密码模式」**且**（配置了 keyPath 或 `ssh -G` 里有 IdentityFile 或 ssh-agent 可用）时才给提示；
- 前端**拿不到 ssh-agent 的状态**（没有命令暴露它），所以只认"诊断证明本机真有一把存在的密钥"这一条 —— 宁可少提示，也不要把"本机已有免密配置"说在一台根本没钥匙的机器上（那会让用户去关一个救命的勾）。

**怎么验的**：3 条单测（有 IdentityFile 就提示 / 有 keyPath 或 agent 也提示 / 关掉密码模式或本机没钥匙时**保持沉默**）；无头断言覆盖"认证失败 + 本机有钥匙 + 勾了密码模式 → 状态栏出现这句提示，并且能点进诊断"。

## 4. herdr 新建会话失败时不再"假报成功"

**改了什么**：`openSshSession` 自己吞掉异常、把会话标成 error、然后**照常返回 id**；herdr 分支拿到 id 就当成功了，紧接着 `notify("已进入 herdr 的窗格…")` 并刷新服务状态。

现在加了一个 `failedSshOpens` 集合：失败时登记这个 id，herdr 分支只有在"这个 id 不在失败集合里"时才报成功、才刷新服务状态；关会话时顺手清掉标记。

**为什么**：真正的认证失败提示是**带「诊断一下」入口**的那一条，却被一句假的成功提示顶掉 —— 用户以为进去了，实际会话是 error 状态，也没有任何下一步线索。这是"假报成功"里最坏的一种：它同时还吃掉了唯一的自救入口。

**怎么验的**：由"连接失败时状态栏仍然是认证失败 + 诊断入口"那条无头用例间接覆盖。**说清楚：这条修复没有专门的用例**（已记进下面的已知问题清单）。

## 5. 「发给 AI」输入框：草稿与附件按会话独立

**改了什么**：把原来一对全局的 `composerText` / `composerFiles` 改成"每个会话一份"：

- `composerDrafts`（ref 里的 Map）存每个会话的正文 + 附件；`composerViewId` 记着当前编辑框镜像的是哪个会话；
- 切标签时先把编辑框写回旧会话，再把新会话的草稿换进来；
- **发送只清当前会话那一格**；关会话才删掉它那一格；
- 「正在上传」也按会话记（A 上传中切到 B，B 不会显示「正在上传…」，上传结果也只会落回 A 的草稿）。

**为什么**：用户报障"在 A 标签写了一半的话会跑到 B 标签下面，甚至被当成 B 的内容发出去"。这是很典型的"共享状态没带上下文"，而且后果不只是丢草稿 —— 是**发错机器**。

**怎么验的**：无头断言 9 条覆盖切换 / 发送 / 附件 / 关会话四条路径：在 A 写正文 + 加附件 → 切到 B（必须是空的）→ 切回 A（正文和附件都还在）→ 在 A 发送（只清 A，B 的草稿不受影响）→ 关掉带草稿的 A（B 不会显示 A 的字 / 附件）。

## 6. tmux 里拖不出选区：Shift 强制选择 + 显式「选择/复制模式」

**改了什么**：两层兜底。

1. **Shift + 拖拽 = 强制本地选择**：xterm 5.5 原生支持（`shouldForceSelection` 就是看 shiftKey），我们只需要**不拦事件**、并在右键菜单里把这件事说出来；
2. **右键 →「选择/复制模式」**（快捷键 `Ctrl+Shift+Space`，`Esc` 退出）：进入时让本地 xterm 解析 `?1000l ?1002l ?1003l ?1006l` 退出鼠标上报，同时把同一串字节镜像给会话；顶部出现提示条（"拖选即可复制 / 拖选后按 Ctrl+Shift+C"、已选中/已复制的字数）。**退出时只恢复进入前真的开着的那些 mode**，不会凭空打开鼠标上报。

怎么知道"进入前开没开"：挂两个 CSI 解析器旁听 `?1000/1002/1003/1006` 的 `h`/`l`（不消费，照旧交给 xterm）。不能只看 `term.modes.mouseTrackingMode` —— 它只保留最后一个 tracking mode，1006（SGR 编码）根本不暴露。

**为什么**：tmux / vim / less 打开鼠标上报之后，xterm 把拖拽当鼠标事件发给远端，本地选不中文字。用户的原话是"tmux 里复制不了东西"。Shift 是 xterm 的既有约定（老用户知道），但新用户不知道，所以还要给一个能点到的入口。

**怎么验的**：无头断言直接盯**原始字节**——进入时向会话写 `?1000l/?1002l/?1003l/?1006l`、提示条出现「Esc 退出」；`Esc` 退出后按进入前状态恢复 `h`；原本没开鼠标上报时退出**不会凭空发 h**。另外：`Ctrl+Shift+Space` 与右键菜单两个入口都在。

## 7. AI 面板暂停用：点开只有一块灰色空容器

**改了什么**：一个全局常量 `AI_PANEL_DISABLED = true`（首发时在 `App.tsx` 顶部；文件拆分后位于 `src/lib/ai-labels.ts`）；活动栏星号仍然能开合面板、宽度还是 268px，但面板体**直接不挂 DOM**（不是 `display:none`），只留一块用主题变量画底色的 `.ai-panel.off`。红点数字、「需要你」chip 也一起不渲染（逻辑还在算，只是没有面板可去，亮个数字只会误导）。

**为什么**：用户原话"AI 助手面板太鸡肋，先关闭；点星号打开只显示个 AI 任务面板"，追问后明确"整个面板都停用，只留灰色容器"。而后续还要重构这套代码，所以选择**留开关、不删代码**：把常量改回 `false`（补发版起还要把 `aiWatchEnabled` 打开，见 §12.1），看板 / 卡片 / 刷新 / 时间线全部回来。

**测试注入的边界（重要）**：看板那 50+ 条无头断言是这套代码唯一的回归网。测试脚本会在页面启动前注入 `window.__ZEEAI_TEST_AI_PANEL__ = true`，只有那一轮渲染内容；**正常启动时这个全局永远是 undefined**，所以生产里一定是灰容器。

**怎么验的**：专门一组无头断言，在注入 `false` 后重载，点星号 → 面板出现、是空的、里面没有卡片 / 按钮 / 「刷新」/ 时间线，且没有红点数字；类名带 `off`、背景是主题的面板底色。另一组仍然在注入 `true` 的轮次里跑原来的看板断言（保证代码没被删坏）。

## 8. 会话标签的 T / H / S 徽标

**改了什么**：每个远程会话标签标题前面加一个小方块：**蓝 T = tmux、绿 H = herdr、黄 S = 纯 SSH**（本地终端 / 串口 / ADB 不加）。普通标签、herdr 接管标签、sub-tab 都用同一个徽标函数；悬停分别写明 "tmux / herdr / SSH"。

判定只看会话对象里**已有的承载字段**（`herdrPane` / `tmuxName` / `tmuxMode`），不靠标题猜：连接中的 tmux 会话先按"这次选的打开方式"标，`tmuxName` 一到就以它为准；`tmuxMode === "none"` 是纯 SSH；`default` 则看服务器配置里 `tmuxEnabled`。

**为什么**：用户说"标签上根本看不出来这个会话是 tmux 还是 herdr 还是纯 SSH"。三者行为差别很大（断线能不能回来、能不能接管），而过去只能靠标题里的文字猜。

**怎么验的**：无头断言 6 条：三个标签分别显示 T / H / S；三种徽标的文字色与底色都不是同一个；悬停分别含 tmux / herdr / SSH；徽标紧挨在标题前；本地终端不加徽标；浅色主题下三种颜色仍然分得开、与浅底对比度 ≥ 3:1。

## 9. 安全与可靠性（架构审查后修复）

这一节每条都是"用户能感知的坏结果"，不是理论风险。

### 9.1 主机密钥 TOFU（新增 `core/known_hosts.rs`）

- **洞**：`sftp.rs` 的 `check_server_key` 以前无条件 `Ok(true)` —— SFTP / 一次性命令 / 密码登录这条路**完全不校验服务器身份**，公共网络里可被中间人冒充；而终端那条路（系统 ssh，`StrictHostKeyChecking=accept-new`）是会拒绝变更密钥的。同一个产品两种安全姿态。
- **改法**：第一次连 `host:port` 记下公钥指纹（OpenSSH 风格 `SHA256:<base64>`）+ 算法 + 时间，放行；之后指纹一致放行且**不写盘**；**不一致直接拒绝**，并在错误里写清"哪个文件、删哪一条"。记录存 `%APPDATA%\ZeeAI-Terminal\known_hosts.json`（和 profiles/settings 分开的独立写路径，但共用同一把写锁）。文件坏了先备份 `.bad-<时间戳>`，再按"首次信任"重来（不能因为一个坏文件把所有服务器都挡在门外），并记 error 日志。
- **验**：7 条单测 —— 首次记录、二次一致且文件一字节不动、指纹变化拒绝且**不覆盖原记录**、多主机累积、坏文件先备份再重来、host key 规范化（大小写 / 结尾点 / IPv6 方括号）、指纹格式（43 字符、无 padding）、以及"换密钥的提示必须告诉用户删哪个文件的哪一条"。

### 9.2 配置 / 历史写盘改原子写

- **改法**：`store::write_atomic` 现在 = 进程内 `SAVE_LOCK` 串行化 + 唯一临时名（pid + 纳秒）+ `sync_all` + Windows `MoveFileExW(REPLACE_EXISTING | WRITE_THROUGH)`。**不再"先删目标再改名"** —— 那两步之间进程被杀就是"配置文件消失"。非 Windows 分支用"旧文件改名备份 → 换新 → 失败再换回来"的兜底。
- `load()` / `load_settings()` 的坏文件路径也改了：**不再顺手用默认值覆盖**，只备份 `.bad-<ts>` 并返回明确错误（以前是"半截 JSON → 静默回落到初始列表 → 用户以为服务器被删了"）。
- `history.json` 以前是唯一一条裸 `fs::write`，这次也接到同一套原子写上（升级安装撞上写盘时不会再出现"会话历史突然空掉"）。
- **验**：3 条单测 —— 原子替换且不留 `.tmp`；**20 个线程并发写**同一目标，落盘的一定是某一次的完整 JSON；坏文件必须先备份、原内容一个字节不变。

### 9.3 ADB 命令注入面

ADB 的 `shell` 只接受一整条命令字符串，过去是 `format!("ls -la '{dir}'")` —— 路径里带一个 `'` 就能闭合引号、在设备上执行任意命令。现在 `ls` / `rm` / `mkdir` 全部走 `remote_fs::sq()`（和 SSH 文件面板同一套转义）。单测用一条带空格、单引号、`;`、`&&` 的路径断言转义结果，并断言普通路径（`/sdcard`、`/sdcard/My Files`）不被改坏。

### 9.4 「打开外部链接」改 `ShellExecuteW` + 白名单

以前是 `cmd /C start "" <url>`：URL 里带 `&` / `|` / `%VAR%` 就能拼出额外的 cmd 命令（用户点一次链接就触发）。现在两层：只允许 `http/https`，且拒绝 shell 元字符与控制字符（命中直接报错，**不静默**）；启动方式换成 `ShellExecuteW("open")`，不经过 cmd。单测断言 10 种恶意/非法 URL 全部被拒、正常链接放行。

### 9.5 其他几处小修

- **`fs_list` 丢 `user_override`（审查 C-03）**：文件面板以前只把"临时换用户"传给了配置解析，真正建 SFTP 连接时仍用默认用户 —— 于是"临时换用户"登录后，文件面板列的还是默认用户的家目录/权限，和上传/下载不一致。现在一路带到连接上（这行原来还留着一个 `unused variable` 的编译警告，一并消失）。
- **多字节 UTF-8 截断 panic**：`&s[..s.len().min(12)]` 按字节切，遇到中文会 panic；改成按 char 截断的 `short_sha()`（用在 herdr 安装进度里显示 sha 前缀）。单测专门造"第 12 个字节落在多字节字符中间"的字符串。
- **tmux 引号统一**：`kill_session` 以前是 `name.replace('\'', "")` —— 名字带单引号时被**静默改名**，结果杀错会话；改成和别处一样的 `quote()`，并补一条单测。

## 10. 输出链路：合并 + 真背压 + 日志 + 指标

**改了什么**（`core/pty.rs`）：

- **合并**：每片 `read()` 先进一个批缓冲，满足任一条件才发一次 Channel —— 攒到 **64KB**、距本批第一片满 **16ms**、或者遇到换行/CR/ESC 时把窗口收窄到 **5ms**（交互式提示符要快，但不能"见换行就发"，否则一行一次 IPC 的老问题就回来了）；1MB 硬上限兜底。字节顺序与内容完全不变，**最后只做一次 base64**。
- **背压**：每批带 `seq`；前端把这一批真正写进 xterm（`term.write` 的回调触发）后才 `session_output_ack(session_id, seq)` 累积确认。后端**最多 2 批未确认**，超过就暂停读 PTY（reader 阻塞 → ConPTY / 远端 TCP 自然减速）；等 ack 超过 **1 秒**记 warn 并推进窗口（丢一次 ack 不能把会话永久卡死）。
- **前端写入队列**：同一时刻只有一次 `term.write` 在跑；本地待写字节超过 **4MB** 时，下一批推迟 16ms 再写（不丢字节，只是让 xterm/WebGL 追上）。高亮后的字符串也走同一条 FIFO。
- **会话日志**：文件名拼 session_id 短哈希（防同名截断，`create_new + append`，冲突加后缀，**绝不用 `File::create` 截断别人的日志**）；全局注册表锁里只克隆 `Arc`，`write_all` / `flush` / 轮转都在锁外；单文件 **64MB 轮转**成 `-1.log` / `-2.log`（补发版起轮转后只保留最近 5 个，见 §12.1）。
- **指标**：每 **10 秒**一行 `perf:`（bytes/s、ipc/s、未确认批次数、本地积压），会话结束再打一行累计（总字节、批次数、平均 ipc/s）。

**为什么**：用户说"终端越用越卡"。查下来的事实是：**每片 read 一次 IPC** —— PowerShell 每 60 字节左右一片，18MB 输出就是 30 万次 IPC，每次还要 base64（+33% 体积）和 JSON 序列化；前端 xterm 的解析是异步的，但后端从不看前端吃不吃得下，于是队列越堆越长。

**实测**（同一台机器、同一份 **30 万行 / 18.2MB** 文本、同一条本地会话，v0.1.13 与本版各跑一次；IPC 次数与批大小取后端 `perf:` 计数，内存取 WebView2 进程峰值工作集）：

| 指标 | v0.1.13 | v0.1.14 | 变化 |
|---|---|---|---|
| IPC 次数 | 304,316 | **13,816** | **−95.5%** |
| IPC / 秒 | 3,566 | **180** | −95% |
| 批大小中位数 | 60 B | **1,380 B** | ×23 |
| WebView2 峰值内存 | 806.7 MB | **579.6 MB** | **−28%** |
| 内存增长（相对空载） | +407 MB | **+178 MB** | **−56%** |

**怎么验的**：

- 单测 8 条（`BatchBuffer` 纯逻辑，不需要真 PTY）：64KB 立即发、16ms 到期发、见换行/CR/ESC 收窄到 5ms 且**不是立即发**、1MB 硬上限、跨片拼接后字节顺序不变、ack 累积语义、超时推进、未确认上限触发暂停；
- 会话日志单测 5 条：短哈希文件名不互相截断、轮转后写到新文件、轮转失败继续写当前文件不 panic、锁外写、停止后 flush；
- 压测就是上表那一次（本地会话 `cat` 一份 18.2MB 文本），前后各跑一次全量 `fe:smoke` + `cargo test`，确认没有回归。

## 12. 同日补发：review 剩余项、前端健壮性与两个巨型文件拆分

这一节是首次发布 0.1.14 之后追加的工作，也是本次**替代发版**的全部增量。三条主线：把 review 里剩下的问题修掉、把前端最容易"白屏 / 丢草稿"的地方补上、把两个改一行要滚半天的巨型文件拆开。

### 12.1 review 剩余项：宁可报错，也不要"假活着 / 假成功"

**改了什么**（按用户能感知的后果归类）：

- **herdr 不再"假活着"**：观察流的输入泵把子进程句柄存进表，每次写入前先用 `try_wait` 判活 —— 进程已经退了就立刻报错并清表，不再把字符静默写进一个没人读的管道；
- **herdr 状态轮询从串行改并发 + 退避**：每台服务器一个任务、聚合结果，一台黑洞机器不再把其他机器一起拖住；失败按 **60 / 120 / 300 秒**退避，连接加 `ConnectTimeout=8` 与心跳，半死连接会自己断开；
- **本机 AI 日志监视不再空转**：按目录 mtime 做缓存，目录没变就是 **0 次 read_dir、0 次文件 stat**；再配合新开关 `aiWatchEnabled`（默认 **false**），面板暂停期间这两条监视线程**根本不启动**；
- **升级链路去掉 `.cmd`**：改为随包的 Rust 辅助进程，参数按 argv 逐个传 —— 安装路径里有 `&`、`%`、`!`、`"` 也只是字符，不会被当成命令或变量展开；
- **sha256 改本地计算**：更新包校验不再调用 PATH 上的 `certutil`，而是进程内按 FIPS 180-4 算，PATH 被塞一个假程序也不会让校验恒真；
- **开启 CSP**：`default-src 'self'`，脚本、样式、图片、字体按实际需要逐项放开；为"检查更新"放开了 `connect-src` 的 https / http，原因写在配置旁（JSON 不能写注释，注释落在 `lib.rs`），并明确标为**待收紧**；
- **错误不再伪装成功**：`run_capture` 非零退出返回失败（以前返回"成功 + 空输出"）；后台任务挂进 Job Object 失败会记告警；SFTP / curl 的英文报错统一中文化；**启动失败改为写 `bootstrap-error.log` + 弹系统错误框**，不再裸 panic（release 是 `panic = "abort"`，用户只看到闪退）；
- **资源与留档**：`log_dir` 结果缓存；会话日志轮转后**只保留最近 5 个**（单会话约占 320MB 上限），不再无限堆。

**为什么**：这些问题的共同点是"出错时看起来像正常"—— 输入泵往死进程里写、`run_capture` 把失败当空结果、启动失败直接闪退、轮转只增不减。用户真正被坑的不是报错，而是**没有报错**。CSP 与 sha256 则是安全底线：一个让渲染层可以被注入内容牵着联网，一个把"官方校验"交给 PATH 决定。

**怎么验的**：全部落在 `cargo test --lib` 的 **207 passed** 里（新增 31 条），包括退避阶梯正好是 60 / 120 / 300、sha256 对 FIPS 公开向量、辅助进程参数把元字符原样保留、轮转只留 5 个、老配置缺 `aiWatchEnabled` 时默认关、启动失败文案必须含"原因 + 日志位置 + 下一步"。CSP 与启动失败弹窗在无头页里测不到，列入待真机验证。

### 12.2 前端健壮性：白屏、丢草稿、脏定时器

**改了什么**：

- **全局 ErrorBoundary**：最外层接住渲染异常，显示一句人话 + 可折叠错误摘要 + 「重新加载」/「复制错误信息」；页脚说明"会话与后端进程不受影响，重新加载后会按恢复工作区的设置回来"；错误页跟随深浅主题；
- **发送草稿持久化**：按**会话身份**（类型 + 服务器 + 登录用户 + 承载方式 + 标题，不用每次启动都变的运行期 id）把正文存进 localStorage，输入后 300ms 落盘；单条上限 20KB、最多留 200 条，超了按最旧淘汰；重启后自动恢复并提示「已恢复上次的草稿」；发送或关会话即删除；**附件不持久化**（只存文本，不把文件内容塞进 localStorage）；
- **5 处 `setTimeout` 补清理**：组件卸载 / 切换后到点的回调不再对已卸载的状态动手；
- **fe-smoke 默认改合成数据**：不再把本机真实 `profiles` / `history` 写进测试临时目录，需要真实数据时必须显式开环境变量。

**为什么**：白屏是最坏的失败模式（用户只能杀进程，还得不到任何线索）；草稿丢失是高频小痛点，而且"重启就没了"和"切标签串了"是同一类信任问题；测试读真实配置既是隐私问题，也是"换台机器就红"的脆弱源。

**怎么验的**：`fe:smoke` 从 187 涨到 **199/199**（+12）。白屏那组会**真的注入一次渲染异常**，断言错误页三要素、错误摘要、两个按钮，以及「重新加载」点下去能回到正常界面、深浅主题都跟得上；草稿那组走真实路径 —— 打字、切走、整页重载、草稿回来、附件不回来、发送后 localStorage 里那份同步删除、再重载不复活。

**改了什么**：这一版没有去动下面四件事，而是把它们**写清楚并记进已知问题清单**，避免"以为已经解决"；`connect-src` 的放宽原因也写进了代码注释，下一版收紧时不用重新考古。

**怎么验的**：CSP 配置、base64 链路、拆分的文件边界都在代码与测试里能对上；真机项**没有自动化覆盖**，已列进下面的已知问题清单，发布后一周内逐项过。

## 已知限制 / 这次没做的

- **合并带来的固定延迟**：普通输出最多等 16ms，带换行/CR/ESC 时 5ms，攒到 64KB 立即发。这对"刷屏"是纯收益，对"一个字符一个字符回显"的交互会有最多一帧的额外延迟（提示符仍然远快于人手感知）。串口不走这条路（没有合并）。
- **仍然是 JSON + base64**：base64 让体积多 33%。要彻底消掉得把 `SessionEvent::Data` 换成二进制通道，那会同时动前端事件形状，不在这一版。
- **ack 超时是兜底、不是保证**：前端 1 秒没确认（页面卡死 / 终端刚好卸载）时后端会 warn 并推进，可能短暂多发至多 2 批；**不丢字节**，丢的是"确认"。
- **会话日志只留最近 5 个**：单文件 64MB 轮转，轮转后删掉更旧的，单会话最多约 320MB；要长期留存请在停止记录后自行转存。日志目录本身仍随 `%APPDATA%` 走，没有单独的清理入口。
- **主机密钥是两套记录**：终端走系统 OpenSSH（它自己的 `known_hosts` + `accept-new`），SFTP / 一次性命令 / 密码登录走新的 `known_hosts.json`。两边不同步 —— 服务器换密钥时，终端那边要 `ssh-keygen -R`，应用这边要删 `known_hosts.json` 的对应条目（错误信息里写了）。`known_hosts.json` 是明文 JSON，没有额外 ACL 硬化，权限依赖用户目录本身。
- **`known_hosts.json` 坏了会"重置信任"**：为了不让一个坏文件挡住所有服务器，坏文件备份后按首次信任重来；这件事**只在日志里**（UI 不提示）。
- **连接诊断只认已保存的服务器**（后端按 profile id 读配置），新建未保存时按钮是禁用的；`ssh -G` 只解析本机配置，**不代表服务器在线或可达**；系统没装 OpenSSH 客户端会明确报错，但不会替你安装。
- **密码模式提示只在认证 / 算法类错误时出现**：网络超时、连不上不提示（跟密码无关）。前端判断"本机有钥匙"依赖诊断结果，**拿不到 ssh-agent 状态**，所以纯 agent 免密、一个密钥文件都没有的机器上不会提示。
- **选择/复制模式是 best-effort**：只能恢复"进入前收到过"的 mouse mode；进入前就已开启、但序列早于解析器注册的，会从 `term.modes` 补一次（只区分 1000/1002/1003，1006 拿不到）。进入模式后远端若再次"开鼠标"，本地会吞掉（否则拖选又会被抢走）。
- **AI 面板暂停用，后端也不跑了**：面板内容不渲染；`aiWatchEnabled` 默认 **false**，本机日志监视与 herdr 状态轮询在启动时**直接不启动**（不是启动了再丢结果）。要恢复面板：把 `AI_PANEL_DISABLED`（`src/lib/ai-labels.ts`）改成 `false`，并打开 `aiWatchEnabled` —— 目前没有设置界面开关，需要改设置 JSON。
- **草稿只存正文**：正文按会话存在本机 localStorage，重启能恢复；**附件不持久化**（重启后要重新添加）；关会话或发送即清除该会话的草稿。
- **T/H/S 只是"承载方式"**：连接中的 tmux 会话先按这次选的打开方式标，拿到真实 tmux 名后才以它为准；本地终端、串口、ADB 一律不加徽标。
- **herdr 假成功修复没有专门用例**：目前靠"连接失败时状态栏保留失败提示 + 诊断入口"那条用例间接覆盖，建议下一版补一条"herdr 建窗格失败 → 不许出现『已进入 herdr 的窗格』"。
- **拆分只搬了代码**：`App.tsx` 仍是状态中心，Zustand 迁移未做；拆分后的主要流程要靠 `fe:smoke` + 真机各跑一遍（无头测试覆盖不到 WebGL、真窗口、输入法）。
- **升级辅助进程只做过本机验证**：`argv` 传参、3010 当成功、结果行回传都有单测，但"下载 → 校验 → 静默安装 → 重启回来"整条链路还没在干净机器上跑过。
- **CSP 只在配置层验证过**：语法与来源清单对得上，但 WebView 里的实际拦截行为（粘贴图片、检查更新、开发热更新）要真机看，`connect-src` 的放宽也还没收紧。
- **上一版遗留的**：OSC 7501 接入仍在等 codex / claude 发布支持版本；看板的历史 / 统计页仍未做（这一版面板还停用了）。
