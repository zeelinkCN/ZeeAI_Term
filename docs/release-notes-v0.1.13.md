# ZeeAI_Term v0.1.13

这一版的主题是**"把没被要求的打扰收掉"**。三件事叠在一起，用户坐在电脑前时一直在被打断：

1. **每十几秒弹一个控制台黑框**（v0.1.12 把探测改成常驻之后，漏了 `CREATE_NO_WINDOW`）；
2. **一直在后台探测**（AI 面板关着也每 8 / 10 / 20 / 30 秒起子进程、跑 ssh）；
3. **红点是"刷新"这个动作造出来的伪信号**（刷新一次就冒一批红点，不刷新就永远不亮）。

这一版把三件一起收掉：所有后台子进程统一隐藏启动；所有定时自动探测删除、只留一个「刷新」；
红点改由**能直接读的来源**驱动（本机 codex 日志 + herdr 状态），**手动刷新绝不产生红点**。
顺带把红点升级成"没点刷新也能更新卡片"，用终端输出流推断"运行中"（只升不降、自己承认是推断），
修掉本地会话"发消息不提交"，删掉用户说"纯属浪费"的「AI 工具」坞。

> 升级方式：安装版「设置 → 检查更新 → 立即下载」；便携版下载新 zip 解压覆盖（覆盖前先关掉窗口）。
> 这一版**仍然只允许同时跑一个实例**（便携版与安装版共用 `%APPDATA%\ZeeAI-Terminal`）。

---

## 1. 控制台黑框：实测 90 秒 27 个 → 0 个

**用户报的原话**："我坐在电脑前，它每隔一会儿就弹一个黑框。"

**根因**：ZeeAI_Term 是 **GUI 进程**（自己没有控制台）。Windows 上 `CreateProcess` 起一个 console
程序（`cmd` / `powershell` / `where` / `reg` / `curl` / `certutil` / `ssh` …）时，只要没带
`CREATE_NO_WINDOW`，系统就会给它**新建一个控制台窗口**，屏幕上就是一闪而过的黑框。
v0.1.12 把看板 / 快照改成常驻之后，这类探测从"偶尔一次"变成"每 10~20 秒一轮"，
**漏掉一个标志就变成"一直在弹本地终端"**。

**改法**：新增 `src-tauri/src/core/proc.rs`，把"起后台进程"收成一个入口：

- `hidden_command` —— 同步命令（要拿输出就 `.output()`）；
- `hidden_command_quiet` —— 连 stdout / stderr 都不要的（升级脚本、`where` 查询）；
- `hidden_command_async` —— tokio 版本（herdr 那条异步 ssh 用）。

三个都带 `CREATE_NO_WINDOW`，并把 stdin 置 null（后台探测不该继承父进程输入、更不该等输入卡住）。
**stdout / stderr 故意不在这里设 null**：`Command::output()` 不会覆盖已经设过的 stdout，
设了 null 之后所有 `output()` 都会拿到空字符串 —— 这是实测踩过的坑（CLI 探测 / certutil 校验会静默失效）。

然后**全仓 17 个调用点**（`commands.rs` / `core/ai_sessions.rs` / `core/herdr_stream.rs` / `lib.rs`）
统一换成这三个函数，原来散落在各模块里手写的 `creation_flags` 全部删掉 ——
`CREATE_NO_WINDOW` 这个魔数现在**只在 `proc.rs` 里出现一次**。

**怎么验的**：仓库里的 `scripts/console-popup-probe.ps1` 用 Toolhelp 快照（含父进程链）
每 50ms 采一次样，同时枚举可见窗口里的控制台类窗口，跑 90 秒统计"父进程链能追到被测 App 的控制台窗口"。
同一台机器、同一套操作路径：**改前 27 个可见控制台窗口，改后 0 个**。

**故意保留显示窗口的两类**（不是漏改）：`explorer.exe` 打开目录（用户就是要看到资源管理器）、
以及用户主动触发的提权 shell（`core/elevate.rs` 的 `ShellExecuteExW runas`，UAC 必须可见）。
终端本身的 pty 由 portable-pty 管，不走这里。

## 2. 删掉「本机 CLI 健康检查 / 一键修」

v0.1.12 加过一版：认出本机 `codex` / `claude` / `gemini` / `aider` 是"没装 / 装了但起不来 / 正在自更新"，
并给一个「重装」按钮。**这一版整条删掉**（用户明确取消）：

- 后端模块 `core/cli_health.rs`（869 行）删除，三个 IPC 命令（`cli_health` / `cli_health_fix` /
  `cli_health_set_flag`）从 `lib.rs` 摘掉，设置里的 `agent_launch_args` 字段删除；
- 前端：看板里的「承载健康 · 本机 AI CLI」块、状态栏那条 `codex 起不来 · 查看` chip、
  悬浮坞里相关按钮、`ipc.ts` 的三个封装、`types.ts` 的三个类型，全部删除；
- 测试：无头断言与假后端里对应的桩一并删除（`cli_health` 在全仓**已经 0 引用**）。

**为什么删而不是加开关**：它每 20 秒自动探一次（一轮 4 个命令：`where` + `<cmd> --version`），
正好是第 1 条黑框的主犯；而这个功能的收益（提前告诉你 CLI 坏了）远不值"每 20 秒打扰一次"。
**"装了但坏了"这件事，用户自己在终端里敲一次就知道** —— 我们不需要替他盯着。

「CLI 承载健康」这一档随之消失，承载健康只剩 herdr 那一路（服务 / 工作区 / 探测失败），
口径没变：**只在异常时出现**。

## 3. 删掉所有定时自动探测，只留一个「刷新」

**用户原话**："把这个功能去掉算了，不探测了，影响电脑性能。"确认后的口径是：
**"保留手动刷新，按钮就叫做刷新。"**

删掉的定时器（全部在 `src/App.tsx`）：

| 定时器 | 干什么 | 代价 |
|---|---|---|
| 8 秒 | `ai_probe` 看当前会话有没有 AI 进程 | 本机枚举进程 / 远端 `ps` |
| 10 秒 | 读当前会话的 rollout 快照 | 本机读文件 / 远端一条 ssh |
| 30 秒 | 顺带看其它开着的会话 | 每个会话一条命令 |
| 20 秒 | 刷看板（远端 `ps` + tmux + 本机进程表） | 最重的一条 |
| 10 秒 | tmux 窗口列表（面板展开时） | 每分钟 6 次 ssh + tmux |

**关键点：这些定时器以前在面板关着时也照跑** —— 那正是用户感觉"影响电脑性能"的来源。
现在它们全部删除，**启动应用、打开面板、切会话都不会自动探测**。

取而代之的是 AI 面板标题栏那一个按钮：**「刷新」**。

- 点一次 = 走完原来那一整轮（状态来源 / herdr 服务 / 时间线 / 快照 / 看板），
  按钮在跑的时候显示「探测中…」并禁用，跑完立刻恢复（**它只是这次点击的进度，不是定时器**）；
- 防连点：`aiRefreshBusy` 这个 ref 挡在同一 tick 里的两次点击；
- **不再有"打开面板就探一次"**：所以新增了一个 `aiSourceProbed` —— 没点过刷新时
  不再显示"探测失败"（那会冤枉一台好好的机器）。

**保留的"用户动作触发"探测**（不是定时器，别混）：打开「新建会话」时探一次那台机器有没有 herdr；
点「刷新」时强制重探状态来源；切到 herdr 会话时探一次**那台机器**的服务状态（状态条要用）。
这三条都是"用户刚做了某个动作"才发生，不是按时间自动跑。

## 4. 红点改由「被动来源」自动驱动

**用户原话**："还是只在 herdr / tmux 等等可以**直接读** AI 的情况下**自动显示**红点，
手动刷新出现红点这种宁可不要。"

所以红点的来源被划成两类，**只有"能直接读"的才允许自动亮**：

| 来源 | 自动亮红点？ | 实现 |
|---|---|---|
| 本机 codex 的 rollout 日志 | ✅ | `core/ai_log_watch.rs`：2.5 秒 `stat` 一次，只读**新增字节**，**不启动任何子进程** |
| herdr 窗格的 agent 状态 | ✅ | `core/ai_herdr_dots.rs`：只对**勾了 herdr 的**服务器、每 **60 秒**调一次已有的 `commands::herdr_agents`（隐藏窗口，不弹黑框） |
| 本应用账本里的任务 | 本机算 / 远端不算 | 本机 codex 走上面那条日志；远端账本没有"进程结束"事件 |
| 进程扫描 / 远程 `ps` / tmux / 裸 SSH / CMD | ❌ | 只能证明"有这么个进程"，不产生红点 |
| 手动点「刷新」 | ❌ | `refreshBoard` **不再调用任何设置红点的代码**；刷新只更新卡片 |

**本机日志那一路为什么最轻**：它只做 `std::fs::metadata` + 读增量（每次最多 2MB，首次 seed 只读尾部 1MB），
解析复用看板同一套 `RolloutParser`；模块里**没有任何 `Command`** —— 有一条单测直接拿源码钉住这件事
（`ai_log_watch_starts_no_process`）。同时过滤掉桌面端 Codex 写的日志（`originator=Codex Desktop`），
不能把"助手在桌面端干的活"当成"你终端里的任务"。

**herdr 那一路的口径**（照用户原话划，不自己扩大）：

- `blocked`（需要你）是**状态**：亮到它不再是 blocked，那一次发 `resolved`；
- `done`（跑完停下）是**事件**：只在该窗格"进入 done"的那一次亮（拿上一轮状态做边沿检测），
  持续 done 不重复、第一次看见就是 done 不补报历史、回退到 working 之后再次 done 可以再亮；
- 窗格消失 / 服务器被取消勾选：还亮着的"需要你"发 `resolved`（否则红点永远挂着一条不存在的事）；
- **失败静默**：连不上 / 超时 / 没装 → 这一轮当"没看见"，只写一行 `log::warn`，不亮也不清；
- **一台勾了 herdr 的服务器都没有 → 一个请求都不发**（`targets_from` 是那道闸门，有单测钉着）；
- 60 秒是**下限**（一轮里 N 台服务器各自最多 20 秒超时，最坏会超过 60 秒，那就下一轮立刻开始，不叠加）；
- 启动后先等 12 秒再跑第一轮，不和首屏 / 恢复会话抢。

**去重**：key 由后端算好 —— 日志是 `log|<rollout 文件名>|<轮次>`，herdr 是 `herdr|<服务器 id>|<窗格>`；
`needs-you` 与 `resolved` 用同一个 key 配对。同一 key 重复送达不会让红点数字往上涨
（后端跨轮去重 + 前端 `prev.includes` 两道）。「需要你」在同一轮里第二次出现（codex 一轮可以问好几次）
会重新亮 —— 去重只吞"重复送达"，不吞"新的一次等待"。

## 5. 被动事件同时更新卡片：不点刷新也能看到状态变化

以前"卡片"完全靠「刷新」那一轮全量数据；红点自动了，卡片还是死的。这一版把同一批**能直接读**的数据
也接到卡片上，**不多起任何探测**：

| 事件 | 谁发 | 带什么 |
|---|---|---|
| `zeeai://ai-log` | 本机日志 + herdr 红点 | 原红点字段 + `instanceKey` / `state` / `activity` |
| `zeeai://herdr-agents` | herdr 那一轮 `agent list` 的**副产品** | 该服务器每个窗格的 `pane/status/agent/cwd/workspace/tab/title` + 统一 `state` |

前端两条路径都归一到同一个 `applyAutoCard`：**已有卡片就地改**（只改 `state` / `activity` / 时间 / 徽标），
**没有卡片就建一张最小卡**（事件里没带的字段一律留空，**不编**）。
自动改过的卡，徽标末尾带「自动更新」—— 这是"这条不是点刷新拿到的"的标记，
点一次「刷新」后整份数据来自后端 `ai_instances`，那个后缀就没了。

三条边界：① 这条链路**不调** `ai_instances`（那等于把「刷新」按钮自动点了一遍，会起进程 / ssh）；
② 空快照**不删卡**（网络抖一下不能让你以为任务没了）；③ `where` / 证据 / 产物这些"刷新才有的字段"
不靠猜，一直等下一次手动刷新。

## 6. 用终端输出流推断"运行中"（只升不降，而且自己承认是推断）

**用户原话**："点击刷新探测 AI 的执行状态不太好，根本不够实时。"

结论不是把探测调快，而是用**本来就在收的终端输出流**：

- `Terminal.tsx` 在 xterm 的 `onWriteParsed` 里记一笔"这条会话刚刚还有输出"（`src/activity.ts`，一个内存 Map，
  无定时器 / 无 I/O / 无 IPC —— 刷屏时它一秒被调很多次，只能 O(1)）；
- 看板渲染时（`src/boardActivity.ts`）把"最近 **5 秒**内还有输出"的会话对应的卡片补成**运行中**，
  并追加一条 `terminal-activity` 证据；卡片上标「**推断 · 输出活动**」，悬停写清它证明不了什么；
- **1 秒的纯 UI 时钟**只在 AI 面板打开时走（`useUiClock`），回调里只有 `setNow(Date.now())`，
  不做任何 I/O —— 它不是探测，只是让"5 秒窗口"这件事每秒被重算一次；
- **只升不降**：输出只能把卡片补成运行中；停下了就什么都不做，回落交给刷新 / 日志 / herdr 给的原状态。
  绝不会推断成"跑完"或"需要你"——那两件事只有日志 / herdr / 进程退出能说；
- **第一手优先**：带 first-hand 证据的卡（herdr）、以及被动事件刚写过的卡（徽标带「自动更新」）一律不碰；
- **不瞎猜**：一张卡对应哪条会话，只认三种确定性证据（显式 sessionId / herdr 窗格 / `where` 里的 cwd），
  而且候选必须**唯一** —— 同一目录开了两个 PowerShell 时不推断，少贴一个标签比贴错好。

## 7. 本地会话回车：40ms → 200ms

**用户报的现象**：从 AI 输入窗发消息，**本地**会话经常不提交（字进了输入框，回车变成换行）；
远程 SSH 一切正常。

**根因**：本地 ConPTY 会把挨着的两次写入合成**同一次 read**（实测只看到一段 `正文 + \r`），
而 codex 对"紧挨着粘贴内容到达的回车"有粘贴突发判定，会把回车当成粘贴内容里的换行。

**实测**（真 codex TUI，每个间隔连续多次，判据是 rollout 里真的出现这条消息 / 页脚出现运行中）：

| 间隔 | 结果 |
|---|---|
| 40ms | 0/3 —— 完全不提交（上一版就是这个值） |
| 80ms | 0/3 —— 完全不提交 |
| 120ms | 3/6 —— 时好时坏 |
| 150ms | 4/6 —— 时好时坏 |
| **200ms** | **4/4** —— 有效样本全中 |

所以本地输入通道（`Terminal.tsx`）与兜底路（`App.tsx` 里直接写会话的那条）**都改成 200ms**。
为什么不是"够快就行"：这个阈值不是协议常数，会随 codex 自己的处理延迟漂移，
所以取实测全中的那一档、再留足余量。多等 160ms 用户察觉不到，漏提交却要手点一次。

## 8. 删掉「AI 工具」坞

右下角那个「▴ AI 工具」浮层（含展开面板、入口按钮、专属样式）整块删除，
连带删掉 `aiStartTool` / `aiToolsVisible` / `DEFAULT_AI_TOOLS` / `aiState`（`AiProbe`）这一串
"探测服务器上装没装 CLI、并从面板里替你敲启动 / 安装命令"的代码。
活动栏那个按钮的 tooltip 改为「**AI 任务看板（需要你 / 运行中 / 最近完成）**」。

**为什么**：用户原话"**纯属浪费**"。它和新的看板重复（看板已经回答"谁在跑、跑到哪了"），
而"在终端里启动 codex"这件事本来就是敲一个词 —— 不需要一层界面代劳；
它依赖的 `ai_probe` 又正好是第 3 条要删的定时探测之一。想看工具装没装，终端里 `where codex` 更快。

## 9. 「最近完成」默认折叠：补上回归测试

**先说实话**：这一版**没有改**这个行为（看板里「最近完成 N 项」本来就是默认收起、点标题才展开）。
改的是**把它钉住**：用户截图里见过"▸ 最近完成 23 项"下面跟着一屏明细，说明这条行为没有测试护着、
随时可能回归，于是补了三条无头断言，用 **23 条历史**造场景：

① 初始默认收起（明细**不渲染**，不是渲染后再藏起来 —— 历史很长时那也是一笔真实的 DOM 成本）；
② 点「刷新」之后**仍然收起**；③ 点标题才展开、再点收起。

为什么值得单独写一节：这类"看起来没坏、其实没人管"的界面行为，一旦回归，
用户第一眼看到的就是一屏不想看的历史 —— 比一个新功能的 bug 更烦人。


## 已知限制 / 这次没做的

- **herdr 那 60 秒是"下限"，不是"保证实时"**：网络差 / 一轮里多台服务器超时时，下一次可能要更久；
  这一轮失败就整轮跳过（不补发 `resolved`），所以红点和卡片可能**滞后一个周期**。
  这是"失败静默 + 不加剧重试"的代价，故意的。
- **`done` 不补报历史**：应用重启后，还停在"等你"的窗格会重新亮（那是状态），
  但"早就跑完停下"的窗格不会补一条"未读"（那是事件）。本机日志同理（首次 seed 只垫状态）。
- **被动来源只覆盖两路**：本机只有 **codex** 会写 rollout 日志，claude / gemini / aider 的本机任务
  没有被动来源；远端只有勾了 herdr 的服务器有第一手 agent 状态。其余承载仍要手动「刷新」才更新。
- **自动更新只改"状态类"字段**：`where` / 证据列表 / 产物列表不会被事件补出来，
  这些要等下一次「刷新」——所以自动建的卡看起来会比刷新出来的卡"薄"一些。
- **输出活动只是推断**：5 秒内有输出 ≠ 在干活（可能是跑完在收尾、也可能是 TUI 在重绘）；
  反过来，**静默 ≠ 停下**（模型思考时可能几十秒不刷屏），所以它只升不降，也不会把卡判成"跑完"。
- **200ms 是实测值，不是协议保证**：codex 改版 / 机器负载变化都可能让它漂移；
  真漂了的话调整点就在 `Terminal.tsx` 与 `App.tsx` 这两处（必须同时改）。
- **删掉「AI 工具」坞之后，不再能从面板一键安装 / 启动 AI CLI**；本机 CLI 健康检查也彻底没了，
  应用不会再主动告诉你"codex 起不来"。
- **探测本身的开销没消失**：只是"用户看不见 + 不再按时间自动跑"；点「刷新」那一下，
