# ZeeAI_Term v0.1.6

这一版三件事：**管理员模式**、**终端关键字高亮**、**AI 任务看板**；另外把上一次
"点了升级却没反应"的那个 bug 连根修掉了。

## 1. 管理员模式（PowerShell / CMD 提权）

以前开的 PowerShell / CMD 都是普通权限，装服务、改 hosts、读受保护目录这类事情做不了。
现在「终端」菜单里有三项：

| 菜单项 | 说明 |
|---|---|
| **以管理员身份重启…** | 弹一次 UAC，**整个应用**以管理员运行；之后开的 PowerShell / CMD / WSL 都是管理员 |
| **以管理员身份打开 PowerShell（独立窗口）** | 不想重启应用时用：单独开一个管理员 PowerShell 窗口 |
| **以管理员身份打开 CMD（独立窗口）** | 同上，CMD 版 |

**为什么是"整个应用提权"而不是"只提权某一个标签页"**：终端是我们用 ConPTY 建的，
伪控制台和管道都挂在应用进程上，Windows 不允许把一个管理员权限的子进程挂进普通权限
进程的伪控制台里（要拿管理员令牌本身就需要特权）。所以走的是业界通行做法 ——
整个终端提权，这跟 Windows Terminal 的「以管理员身份运行」是同一个模型。

当前是管理员模式时，**底部状态栏会显示「🛡 管理员」**，一眼能确认。

## 2. 终端关键字高亮

日志里的关键词自动变色，不用再一行行找：

- 开箱预设四套：**ERROR / FAIL / Exception**（红）、**WARN**（黄）、**OK / SUCCESS**（青）、
  **panic / assert / watchdog**（白字红底）；
- 规则可自己改：「视图 → 关键字高亮…」或设置里打开，能配**关键词、区分大小写、
  前景色 / 背景色、只给关键词上色还是整行上色**，面板里有实时样张；
- **SSH、串口、本地终端共用同一份规则**；
- **日志文件不受影响**：高亮只在界面生效，落盘的终端日志仍然是干净纯文本
  （写盘是后端从 PTY 原始字节走的，本来就会剥掉颜色码）。

实现上走"数据流注入"：在交给 xterm 之前把命中的关键词包上颜色。两个关键细节 ——
**分块边界只挂住"尾部可能是关键词前缀"的几个字符**（不为了匹配把整行挂起，否则打字回显会卡）；
**插入颜色后按终端当前颜色状态恢复原色**（不会把彩色输出后半行弄掉色）。

已知取舍（v1）：改规则**不会重新着色历史输出**；不支持正则（写 `.*` 会把渲染拖死，
留到 v2 并限量限长）。

## 3. AI 任务看板

AI Agent 面板上半部分现在是**多环境汇总卡片**，一张卡片 = 环境（本地 / 远端 / WSL）+
服务器 + 命令 + 运行中·已结束 + 耗时 + 来源：

```
● OpenAI Codex CLI        [远端]   运行中
  生产机 · main:0.1 · 起于 21:04:11
  node /usr/local/bin/codex
  耗时 12 分 30 秒 · App 启动（最准） · pid 41822
```

信号源按可靠度分层，越靠前越准：

| 层 | 怎么拿到 | 特点 |
|---|---|---|
| App 自己启动的 | 点「在终端启动」时记一笔 | 开始时间、跑完没跑完都由 App 判 |
| 远端 tmux 窗格 | `tmux list-panes -a` + 进程树 | 能精确到**哪个会话的哪个窗格** |
| 远端 `ps` 扫描 | 一条 shell 命令 | 只能告诉你"这台机器上有" |
| 本机 PowerShell | `Get-CimInstance Win32_Process` 读 CommandLine | 全进程表扫描偏重，20 秒才一次 |

几个刻意避开的坑：**WSL 里的进程会进 WSL 里面查**（Windows 侧只能看到 wslhost/vmmem）；
**CMD 没有脚本钩子，只显示状态**；TUI 拿不到百分比，所以**不做进度条**；
判定只看**可执行文件名和解释器参数**（`node /usr/local/bin/codex` 认成 codex），
**不看输出文本** —— 否则日志里出现 "claude" 字样就会误报。

## 4. 修复：一键升级不再"点了没反应"

0.1.5 有用户遇到：下载好了新版本、点了安装，应用退出后再没回来，版本还是旧的。
查清楚了，是一个**下载坏了包**的问题：

旧的下载是 1MB 分片 + 追加写，而分片的文件句柄会交给 `curl` 直接写。中间有一次分片请求
卡住没返回，应用退出后那个 `curl` 变成了**孤儿进程继续往同一个文件里追加**，和后一次
（重启应用后）的下载**交叠写入** —— 结果文件大小最后刚好等于官方大小，但内容已经错位。
安装器打开这种包会报 "NSIS Error"（自带的完整性校验失败）然后**静默退出**，而当时的
升级脚本不看退出码，于是就成了"点了升级，什么都没发生"。

这一版把这条链路按四条规矩重写了：

1. **不要出错** —— 整包最多自动重下一次；失败会写日志、把坏包丢掉、并把旧版重新拉起来；
2. **不要死锁** —— curl 带连接超时和低速超时（60 秒低于 2KB/s 直接判失败重试），
   stderr 写文件而不是管道（管道没人读会互等），并且 curl 挂进 Job Object，
   **应用一退它就跟着被收掉**，不会再留孤儿进程；
3. **不要分片** —— 一次请求整包下载，不再用 Range 拼分段（分片追加写正是上面那个事故的根）；
4. **不要下错** —— 下完先落到 `.part`，校验 **大小 + 文件头 + 官方 sha256**
   （GitHub Release API 里的 `digest`，用系统自带 `certutil -hashfile` 算），
   全过才原子改名成正式安装包。

另外，升级脚本现在**有上限地**等主程序退出（最多 2 分钟，超时强杀），并且**会看安装器的
退出码**：不为 0 就记一行日志、丢掉这次下的包、把旧版拉起来。下次启动时状态栏会提示
上一次的升级结果，不会再出现"什么都没有"。

## 升级方式

- 已经是 **0.1.5**：设置 → 检查更新 → **一键升级到 0.1.6 并重启**（这一版的下载链路已经修好了）；
- 还在 **0.1.3 / 0.1.4**：建议**手动装一次**本版（老版本的下载链路还是分片的，可能碰到上面那个坏包问题）；
- 0.1.2 或更早：需要手动装一次。

配置存在 `%APPDATA%\ZeeAI-Terminal\`，升级不会丢。

## 已知限制

- 仅 Windows；未做代码签名（首次运行 SmartScreen 会提示"未知发布者"）
- **管理员模式只能整个应用提权**：单个标签页提权在 Windows 上做不到（原因见上文），
  不想重启应用时请用「以管理员身份打开 PowerShell / CMD（独立窗口）」
- 关键字高亮：改规则不重着色历史输出；不支持正则
- AI 看板：WSL 目前按默认发行版查；纯探测到的进程退出后直接从看板消失
  （只有 App 自己启动的那批会留一张"已结束"卡片，可手动清）
- 一键升级依赖系统自带的 `curl.exe`（Win10 1803+ 内置）；下载速度取决于你到 GitHub 的线路
- tmux 面板用的是 tmux 2.x 以上的通用命令，没测过非常老的 tmux（1.x）
