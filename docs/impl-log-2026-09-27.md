## 3. 这轮**没做**的（以及为什么）

不是忘了，是判断"现在做风险大于收益"，列出来给你点名：

| 编号 | 为什么先不做 |
|---|---|
| T-12（AI 探针 400KB 窗口漏报） | 真正的修法是"按 offset 增量读 + 自适应窗口"，要改远端脚本和状态管理。这轮先不动，避免把 0.1.7 刚稳定的通知逻辑改出新问题 |
| T-13（每条会话新起 ssh） | 需要合并三路探针或做连接复用，属于结构性改动 |
| T-14（本机 WMI 扫描 0.8~1.1 秒） | 换成 `tasklist` 会损失命令行信息（看板靠它认工具），需要先想清楚替代方案 |
| T-17（单窗格下所有会话都挂载） | 改成延迟挂载会影响 `SessionBus` 的缓冲语义，容易引入"切回去丢输出"，要单独排一次 |
| T-25（前端 848KB 单包） | 动态 import markdown-it/DOMPurify 会碰预览渲染路径，收益（本地加载）远小于风险 |
| T-29（WebView2 嵌入安装模式） | 会让安装包变大，与你"省流量"的诉求相反，需要你先拍板 |
| T-27（少发产物） | 属于发版策略，等你定 |
| T-32（拆分 App.tsx / commands.rs） | 结构性重构，绝对不能和功能改动混在一轮 |
| `tmux attach -d`（让 attach 互斥） | **这是产品决策**：加了之后，从手机/另一台机器 attach 会**把桌面端踢掉**。我不替你决定 |

## 4. 两件需要你知道的事

### 4.1 冒烟测试把"多客户端"这个问题现场演示了一遍

我启动便携版时，你的**安装版也在运行**，两个实例都 attach 了 `codexAAA` —— tmux 那边立刻变成
另一个尺寸（我读到窗口从 84×65 变成 118×36）。这就是 `bug-tmux-scrollback-narrow.md` 里说的
那个机制。所以我在验证完之后**立刻把便携版关掉了**（只关了它，`pid=83208`），没有留在那里继续挤你的会话。

> 提醒：这台服务器上的 tmux 是 **2.7**，同一个会话挂两个客户端时按**最小的**那个算尺寸。
> 所以**如果你要试新便携版，建议先把你现在那份关掉再开**，否则两边会互相改尺寸。

### 4.2 构建会在系统里留下"已安装 ZeeAI_Term"的事件，这是旧现象

我在查别的事情时顺手看了 Windows 事件日志，发现从 09-24 起**每天几十条**
"Windows Installer installed the product: ZeeAI_Term"（0.1.0 → 0.1.7 一次没落下，包括我这次的 12:38）。
查下来它**不留下任何实际安装物**：没有 `C:\Program Files\ZeeAI_Term`，注册表里也没有 MSI 产品记录，
只有你那份 `%LOCALAPPDATA%\ZeeAI_Term`（NSIS，0.1.7，16.6MB）—— 那份**完好无损**。

我倾向它是 WiX 打包步骤的副作用（每次 `npm run tauri build` 都会来一次），不是新问题，
也没有需要清理的残留。但如果哪天你在"应用和功能"里看到奇怪条目，这条线索能用上。

> 另外：`%TEMP%\ZeeAI-Term-update\` 里躺着 0.1.2 / 0.1.4 / 0.1.5 / 0.1.6 四个旧安装包
> （其中一个还叫 `.corrupt-20260926`，1MB 半截包）—— 这是 T-03 那个 bug 的实物证据。
> 我没删它们（那是你 TEMP 里的文件）；新代码会在**下次升级时**自动清掉。
