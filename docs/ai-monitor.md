# AI 状态观察 · v0.1.15

本次经用户确认恢复 AI 面板，范围收窄为 **ZeeAI 当前打开或接入的远端 Claude Code / Codex 会话**。不恢复旧版全进程/日志探测，也不采集外部终端中的任务。本文是当前实现口径，旧 `design-ai-board-v2.md` 保留为设计档案。

## 用户看到什么

- 「需要你」位于最上方，区分等待批准、回答、登录以及运行出错。
- 「运行中」展示程序真实上报的状态；若 CLI 自己提供百分比才展示进度。
- 「最近完成」折叠收纳；完成指一轮交互结束，不表示用户的整体目标已经实现。
- 空闲、未收到状态和连接异常放入「空闲与待确认」，不占用活动卡片区。
- 卡片显示服务器、会话、目录、来源与更新时间，可直接切回原终端。批准/输入操作仍由用户在终端完成。
- 默认只显示需要处理和完成未读的数字。等待处理状态不会因为打开面板就消失；完成未读打开面板后清除。每轮完成的额外提醒默认关闭，任务栏/Dock 提醒可选。
- 收起面板继续观察；关闭会话、暂停观察或退出应用后停止。远端任务是否继续取决于 SSH/tmux/herdr 环境，不由监控推测。

## 数据来源

### 普通 SSH 与可透传的 tmux

在 `SessionBus` 新字节入口解析 OSC 7501，早于 xterm 渲染和高亮，不随终端组件重挂载重放状态。查询响应直接写回同一会话，不经过粘贴/提交逻辑，每会话有限流。只识别有明确 Claude/Codex 身份的报告及其子记录。

流解析器处理任意分片、BEL/ST 结束、大小限制、base64 UTF-8、层级记录与清除；保持有界内存。只读 herdr 流不回答终端能力查询、不向观察对象注入按键。

CLI 支持基础来自 [Claude Code 终端文档](https://code.claude.com/docs/en/terminal-config#see-session-status-in-your-terminal)、[Codex 0.163.0 变更记录](https://learn.chatgpt.com/docs/changelog?date=2026-10-15)、[OSC 7501 规范](https://www.superlogical.com/rex/docs/build/program-status)。支持协议不代表所有 tmux 版本都能传递；Claude 文档明确指出它会查询 tmux 自身，单纯开启 allow-passthrough 无法保证收到状态。无法接收时显示待确认，不通过屏幕关键字或输出安静时间猜测。

### herdr TUI 窗格

沿用仓库已有的 **herdr TUI** 会话集成（`herdr terminal session observe/control` 与 `herdr agent list`），不把另一套 `herdr-core` / Herdr 桌面应用宣称为同一协议。

前端只提交当前已连接会话 ID；Rust 从 SessionRegistry 与 HerdrPaneRegistry 取实际绑定的服务器/用户/窗格，并校验连接仍然存活。按服务器配置与有效用户合并请求，首次立即，之后成功最短 60 秒；失败退避至 120 / 300 秒。暂停、重开面板、增加同账户窗格均不能绕过频率下限。

使用专门的只读命令查询，不启动 herdr 服务。合法空列表、未安装、服务停止、无效输出、SSH 失败分别处理。快照只向前端发送当前打开窗格的 Claude/Codex 状态；在返回前再次检查 scope 和连接身份，丢弃关闭/暂停后的过期结果。没有待观察连接时等待通知，没有周期 SSH 请求。

会话绑定打开时的连接配置与 `ssh -G` 生效配置摘要；应用内服务器配置或外部 SSH 别名的目标、用户、密钥、代理等变化后，停止该连接的监控并提示重连，避免把结果归到旧会话。只保存摘要，不记录配置明细。

herdr 返回的是它的识别结果，准确性与服务端版本及适配有关，不能一概称作 AI 自己的第一手报告。每分钟查询可能漏掉两次采样之间的短暂状态。

## 状态与提醒约束

1. 只有显式 `done` 报告或 herdr 从已观察的运行/等待状态进入 done，才产生完成事件。
2. 初次接入看到 done 不补报历史；相同 blocked/done 重复报告不重复通知。新一轮工作后可以再次提醒。
3. 多个层级记录合成一张会话卡：等待处理优先，仍有工作子项时不提前报告整张卡完成。清除记录和 shell 提示符本身不生成完成事件。
4. 断线、安静、进程消失、合法空列表或查询失败都不算完成。检测失败保留上次基线、展示待确认，恢复相同状态不重复提醒。
5. 不读取或上传 AI 对话历史，不自动批准权限，不改写远端 CLI 配置，不为本特性安装服务端守护进程。

## 验证

`npm run test:ai` 验证协议流与状态机；`npm run fe:smoke` 使用合成数据运行 Windows 浏览器功能测试；`node scripts/ai-monitor-smoke.mjs` 在 Mac Chrome / Windows Edge 验证真实生产面板、分片查询、同批首帧、resize 重订阅、提醒与断线。`cargo test --locked --lib` 验证账户分组、范围、频率、失败退避、过期结果和原有后端功能。双系统安装包由 GitHub Actions 原生 runner 生成，具体结果记在发布说明中。
