# ZeeAI_Term v0.1.10

这一版没有新功能，主线是**把"看着不对"的地方修正过来**：AI 看板不再把助手自己的活算成你的任务、
浅色主题下那些"深底深字"的框、终端开多了会花屏变慢、以及"文档承诺了但实现没有"的三处漂移。
外加两条"规矩"上的加固：自检/演示代码不再编进发布二进制，应用变成单实例（便携版与安装版
共用同一份配置，以前两个一起开会互相覆盖）。

> 升级方式：安装版直接「设置 → 检查更新 → 立即下载」；便携版下载新 zip 解压覆盖
> （覆盖前先关掉正在跑的窗口）。
> **注意**：这一版起**同时只允许跑一个实例** —— 如果安装版开着，双击便携版只会把安装版的窗口
> 叫到前面来（反过来也一样）。这是故意的：两者共用 `%APPDATA%\ZeeAI-Terminal`，
> 同时开会互相覆盖设置与历史。

---

## 1. AI 看板：不再把"桌面版 Codex 自己的活"当成你在终端里的任务

**你报的现象**：AI 任务看板报出"本机 PowerShell 里有 Codex 在跑"，可当时 PowerShell 里
什么都没跑 —— 桌面上真正在干活的是另一个客户端。

**根因**：桌面版 Codex / VS Code 扩展把自己的会话日志写进**同一个** `~/.codex/sessions`，
而本机快照只认"最新的那一份"。实测你机器上 **21 份 rollout 全都是** `originator=Codex Desktop`
—— 于是助手的每一轮回复都被记成"你在这个 PowerShell 会话里跑的任务"，连它改过的文件都顺着
`cwd` 挂成了"任务产物"。

**修法**：按 rollout 头部的 `originator` / `source` 过滤（含 `desktop` / `vscode` 的一律不读），
并从新到旧逐个找**用户自己那份**；一份都没有就返回"没有"。

一个容易踩空的细节：判断"谁写的"必须读**文件头**（`session_meta` 是第一行）——
你那些日志最大一份 **98MB**，4MB 的尾巴窗口里根本没有它。

**实测**：本机 21 份全是桌面端 → 本机不再出卡片；临时造一份用户在终端里跑 codex 的日志
（`originator=codex_cli_rs`）→ 正常认出来（证明没修过头）。

> 历史里那几条 09-29 的旧记录是**落盘数据**（`ai_turns.json`），修复只保证不再新增 ——
> 旧的点「最近任务」右边的 ✕ 清掉即可。

## 2. AI 看板：只摆"任务"，不摆"窗格现状"

| 以前 | 现在 |
|---|---|
| 面板标题是「AI Agent · 当前会话」，下面却列着**远端**的卡 —— 这是"它探测到我的 PowerShell"这个误会的直接来源 | 标题固定成「AI 任务看板」；每张卡自带环境标签（远端 / 本机） |
| 陈旧的 `空闲` / `已完成` 窗格一直占着卡片位 | 收进一行「另有 N 个不活跃的窗格」，默认不占地方，点开才看 |
| 不活跃的卡也摆着「查看窗格 + 接管」两个按钮，看着都能点（其实切不过去） | 不活跃的卡只留「查看窗格」；已经开着标签的才给「切到标签」 |
| 卡片副标题出现 `lz · lz · w1Q:p1`（服务器名与项目目录名重复） | 去重成 `lz · w1Q:p1` |

**没做成的一条**：原计划"超过 30 分钟没动静就不显示" —— herdr 的 `agent list` **不给最后活动
时间**，拿不到就不假装有，改成"一律折叠、要看点开"。

> 顺带说明：通知口径本来就只在「等你处理」和「产出新文件」时响，`空闲 / 已完成` 从来不通知 ——
> 这条复查过，无需改动。这次改动只影响"看板摆什么"。

## 3. 浅色主题：那些"深底深字"的框

**你报的现象**：切到浅色主题后，设置里一排深灰色的框（按钮、两个滑块）压在白底上，
文字是深色的，几乎读不出来。

**根因**：主题只换 CSS 变量（`--bg` / `--fg` / `--border`…），而按钮 / 输入框的底色是**写死的深灰**；
两个滑块更彻底 —— 样式表里**一条 `input[type=range]` 都没有**，套用的还是输入框那个深灰底。

**修法**：把控件底色收进主题变量（`--btn-bg` / `--field-bg` / `--panel-2` / `--code-bg` /
`--code-inline-bg` / `--hover`），`.app.light` 一套值同时管住 5 套浅色主题；
给滑块补上轨道 / 滑块的显式样式；顺手删掉几段因此变得多余的"按组件打补丁"覆盖。

**顺手揪出更隐蔽的一条**：`.app` 从来没设 `color`，于是所有"没写颜色"的文字都继承 `body` 上
写死的 `#cccccc` —— 浅色下就是"浅底浅字"（设置对话框那个标题「设置」几乎看不见就是这么来的）。

**以后不会再靠你截图发现**：`fe-smoke` 里加了一条对比度审计 —— 切浅色后**逐页**翻设置面板，
把每个直接装着文字的元素按真实计算样式算对比度，低于 4.0 就红；深色主题另有一条不回归断言。

## 4. 终端：开十几个会话不再把 GPU 上下文挤爆

单窗格模式下**所有**会话都挂着终端（用 `display:none` 藏着，为了不丢回滚缓冲），而每条都会挂一个
WebGL 渲染器 —— 上下文数量有上限，超了最先创建的那条会被丢掉，表现就是花屏 / 越用越慢。

现在只有**看得见**的终端才挂 WebGL（单窗格 1 个、分屏最多 4 个），藏起来时摘掉、退回 DOM 渲染；
终端本体、回滚缓冲、连接都不动。上下文丢失后的自动重建（0.1.9 已带）保留，并且重建前会先确认
"这条还看得见"，避免又变回"N 个占 N 个"。

## 5. 更规矩一点

- **自检 / 演示代码不再编进发布二进制**。`ZEEAI_SELFTEST` / `ZEEAI_AUTODEMO` 现在是
  `--features selftest` 门控的。以前任何能设环境变量的本地程序，都能让应用对你**自己的服务器
  和手机**做真操作（上传、改目录、删文件、往服务器装 herdr、`adb kill-server`）。
  逐字节比对确认：新 exe 里搜不到这两个字符串，旧版能搜到。
  开发时要跑自检：`cargo run --features selftest`。
- **单实例**：便携版和安装版共用同一份配置目录，以前两个一起开会互相覆盖 settings / history /
  workspace（后写的赢），通知也会各弹一遍。现在第二个实例只把已有窗口叫到前面来，然后自己退出。
- **文档口径**：README 里"便携版可一键升级"（实现其实是明确拒绝）、"14 套终端配色"（实际 15 套）、
  Fastboot 的措辞（只有"看设备/看版本"，不能刷机）三处对齐。
  并新增 `scripts/check-docs.mjs`，**挂进发版脚本第 1.5 步** —— 这几条以后由发版前自动核对，
  不再靠人记。

## 已知限制 / 这次没做的

- **WebGL 那条没有自动化覆盖**：无头 Edge 里 `webgl2Available()` 是 false，整条路径进不去，
  fe-smoke 只能证明"没把别的搞坏"。真机上建议开十几个会话来回切一遍看看。
- 时间线里的旧记录（`ai_turns.json`）**不会自动清理** —— 修复只保证不再新增，旧的需要手动清。
- 「超过 30 分钟没动静就不显示」没做（原因见上）。
- 前端 bundle 里还留着 `zeeai://autodemo` 监听（后端事件已经编不进去了，等于死代码，无风险）。
- 终端画布底（`.pane`）仍是深色 —— 终端配色是**另一套**设置，深色终端 + 浅色界面是正常搭配。
- 设置面板之外还有一处颜色没跟浅色主题：左侧图标栏的图标色（浅色下 3.1:1，偏淡）。
- 审计里其余待办（同一台服务器被三处轮询各自新起 ssh、更新包哈希走外部 `certutil`、
  `local_snapshot` 的同步 IO 在 async 命令里、CSP 为 null 等）都记在
  [docs/backlog.md](backlog.md) 里，带改法与验收标准。
