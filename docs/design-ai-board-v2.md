## 0. 摘要（TL;DR）

- **现状**：屏幕上有三块地方在说同一件事（AI 面板的卡片区、面板里的「最近任务」时间线、底部状态栏），
  外加两处"服务健康"（终端上方的 herdr 状态条、面板里的 herdr 服务行）。状态来自**五套互不相干的来源**
  （herdr 第一手 / 远端 tmux+ps / 本机进程表 / App 自己的账本 / rollout 日志），合并规则是**两趟打补丁**
  （`src/App.tsx:1480-1509`），而且**每张卡不标"这条信息有多可信"** —— 于是"推断"经常被读成"事实"。
- **新方案一句话**：**看板上只有一个实体：AI 实例**。给它一套统一的状态词（5 个）、一份**证据列表**
  （谁说的、什么时候说的、多可信），界面上只分三层（需要你 / 运行中 / 最近完成），时间线退化成
  "实例的历史"而不是独立一区，状态栏只留会话与连通性 + 一个「需要你」入口。
- **兼容**：本地 PowerShell / CMD / WSL、远端裸 SSH / tmux / herdr —— **同一套界面、同一套状态词**，
  但每张卡带**来源徽标**，拿不到的状态**如实降级**（裸 SSH 永远不显示"等你处理"）。
- **落地**：拆 4 步（M1 统一模型 → M2 分区收口 → M3 可信度与降级 → M4 状态栏与健康收口），
  每步可独立验收、独立发版；验收尽量写成 `scripts/fe-smoke.mjs` 断言。
- **需要你拍板 4 件事**：见 §9（分区怎么分、时间线要不要合并、状态栏留什么、CMD/裸 SSH 要不要显示）。

## 1. 文档目的与范围

**目的**：把"AI 看板 / 状态栏 / 任务看板"从"一路打补丁长大的三块 UI"重做成**一个模型 + 一套词 + 三层界面**，
并且让它在五种承载上都说得过去（本地 PowerShell/CMD/WSL、远端裸 SSH/tmux/herdr）。

**为什么要写文档而不是直接改**：现状的问题不是"某处画错了"，而是**实体定义错了**
（以"任务卡"为中心，而不是以"AI 实例"为中心）。这决定了改法：改一个字段没用，
得先把"什么是一个实例、它的状态由谁说了算"定下来，否则每加一种承载就要再打一趟补丁
（历史上已经发生过：`src/App.tsx:1476-1488` 的注释记着"两个 codex 只剩一张卡"那次）。

**范围**：AI 面板（含卡片区、时间线、herdr 服务行）、终端上方的 herdr 状态条、底部状态栏中与 AI 有关的部分、
以及它们背后的数据模型与采集。**不含**：终端本身、SSH/tmux/herdr 的连接与接管逻辑、文件传输坞、
工具坞的安装能力（只在 §3.2 建议把它收进「＋」菜单）。

**不变量（本次不能回退的能力）**：终端与五种承载照常可用；AI 面板现有的信息一条不丢（可换位置、不可消失）；
通知开关（`App.tsx:702-710`）语义不变；`ai_turns.json` 时间线落盘与"清空"入口保留
（`ai_history.rs:58/80/112`、`App.tsx:8152-8160`）。

### 2.2 五套数据来源：能拿到什么、拿不到什么、多准、多快

| 来源 | 代码入口 | 能拿到 | 拿不到 | 延迟 | 能不能当"真相" |
|---|---|---|---|---|---|

| **远端 tmux + ps 脚本** | `ai_tasks.rs:92-106`（脚本）、`108`（解析）、`commands.rs:1682` | "这台机器上有一个 codex 进程"、命令行、`etimes`（已跑秒数）、tmux 窗格标签 | **任何状态判定**（在跑 / 等你 / 报错了都长一样）、token、产物 | 看板刷新时代价（一次 ssh 跑脚本） | ⚠️ 只能证明"存在"，不能证明"在干活" |
| **本机 Windows 进程表** | `ai_tasks.rs:197`（脚本）、`269`（`scan_windows`）、`commands.rs:1748-1773` | 同上（本机版） | 同上 | **最多 60 秒一次**（`App.tsx:726` + `1465`，实测起一个 PowerShell 枚举进程 0.6~1s，`1463` 注释） | ⚠️ 同上 |
| **WSL** | `commands.rs:1719-1747`（进 WSL 跑同一份 ps 脚本） | 同"远端 ps" | 同上（且 Windows 侧看不见 WSL 里的进程，`ai_tasks.rs:12-13`） | 同本机限流 | ⚠️ 同上 |
| **CMD** | `commands.rs:1718`（直接 `None`） | **什么都不扫**（`ai_tasks.rs:14` 明确"C MD 没有脚本钩子 → 仅状态"） | 一切 | — | ❌ 只能显示"这个会话存在" |
| **App 自己的账本** | `ai_tasks.rs:493-530`（`AiTaskRegistry` / `note_start`）、`543`（`merge`）、`App.tsx:2311` | **精确**的开始时间、命令行、启动者是我们自己这件事 | 只有 App 启动的那些；不覆盖用户手敲的 | 事件驱动（立即） | ✅ 对"我们自己起的"是事实 |
| **rollout 日志**（codex） | `ai_sessions.rs:124-143`（字段）、`162`（`parse_rollout`）、`828`（本机）、`804`（远端脚本解析）、`25`（4MB 扫描窗口） | 最后一句话、**state**（running/idle/needs-approval/waiting-user）、token 用量、上下文窗口、审批策略、产物文件（`689`） | 只有 codex；本机还要排除桌面端写的日志（`863-895`，见 §2.4-①） | 当前会话 10s、其它会话 30s（`App.tsx:2279-2280`） | ✅ 状态与"最后一句话"可当事实；**仅限 codex** |
| **落盘时间线** | `ai_history.rs:18-51`、`App.tsx:1552` | 完成时间、耗时、token、产物清单、当时那句话 | 运行中的事（事后才有）、跨机器全局视图 | 事件驱动 + 手动刷新 | ✅ 对"已经发生的事"是事实 |

**一句话结论**：**只有 herdr 与我们自己的账本/日志能在"状态"上说话**；进程扫描只能证明"存在"。
现界面把这两种可信度**画成了同一个样子** —— 这是"太杂乱"与"误以为它在探测我的 PowerShell"的共同根因。

### 2.3 重复与冲突（逐条，都能指出位置）

1. **同一件事两处出现**：一轮跑完，卡片区出现一张"已完成"的卡，时间线再记一条（`App.tsx:7950-8130` 与 `8136-8250`）。
   两处的字段几乎一样（工具/服务器/目录/耗时/产物），只是**排序与折叠规则不同**。
2. **两套状态来源并存，靠合并规则缝在一起**：同组同窗格的卡由 `betterTask` / `absorbTask`
   按"源越准越优先（App > herdr > tmux > ps）"合并（`App.tsx:397-416`），并把"看得见窗格"的字段保住（`410-416` 注释）。
   这是**正确的补丁，但补在了错误的地方** —— 它说明实体键一开始就没定对。
3. **合并粒度改过一次，留下两趟规则**：第一趟按 `taskKeyOf`（环境+服务器+工具+目录+窗格，`389-391`）；
   第二趟再把"说不出自己在哪个窗格"的并进同组里带窗格的那张（`1489-1509`）。
   两趟才等价于"一个实例一张卡"——**如果一开始就用"实例"当主键，两趟都不需要**。
4. **"仅有状态"的卡与真卡片同区**：CMD 只能给"这个会话存在"（`ai_tasks.rs:14`），却和 herdr 的第一手卡并排显示。
5. **可信度不标在卡上**：面板顶部只有一行"状态从哪来"，而且是**针对当前会话**的（`App.tsx:7758-7770`）；
   一张远端的卡和一张本机凭进程猜出来的卡长得一模一样。
6. **状态词有三套**：`herdrStateLabel`（`App.tsx:442-455`）、`board_state`/`state_label`（`herdr.rs:225-238`）、
   会话的 `stateText`（状态栏用）。三套词表同义不同名，翻译关系靠人脑。
7. **"活跃 / 陈旧"的边界藏在折叠里**：`isActiveBoardTask`（`App.tsx:464-470`）+ `inactiveOpen`（`1109` / `2833`）
   —— 默认只显示"活跃"，但**什么算活跃**（herdr 的 working/blocked，没有 herdr 时退回进程死活）对用户不可见。
8. **通知判据分散在三处**：`considerSnapshot`（`2100-2210`，日志轮次）、herdr blocked（`1512-1529`）、
   时间线写入；去重靠两个 ref（`aiHandledTurns` `1094`、`herdrNotified` `1054`）。

## 3. 新方案

### 3.1 唯一实体：AI 实例（`AiInstance`）

**为什么以"实例"为主键**：一张卡要同时回答三件事 —— "有几个"（两个 codex 要两张卡）、
"谁说的"（herdr 第一手 / 进程推断）、"点它能去哪"（标签页 / 观察窗）。
现状用"任务卡 + 两趟合并"来逼近这三件事（§2.3-2/3）；换成"实例"当主键，三件事自然成立。

字段设计（`必填` / 可选；"来源"列决定可信度）：

| 字段 | 必填 | 来源 | 说明 |
|---|---|---|---|
| `id` | ✅ | 派生 | 稳定键 = `承载 + 归属 + 实例锚`（herdr: `pid:pane`；tmux: `会话:窗口.窗格`；裸进程: `pid`；App 账本: 启动时生成的 id，`ai_tasks.rs:504`） |
| `carrier` | ✅ | 派生 | `local-powershell` / `local-cmd` / `wsl` / `ssh-bare` / `tmux` / `herdr` —— **界面按它决定"能承诺什么"** |
| `agent` | ✅ | 进程名 / herdr `kind` | codex / claude / aider / gemini / 未知 |
| `where` | ✅ | 各家 | 环境（本机/WSL/服务器名）+ 目录 + 窗格/工作区 |
| `status` | ✅ | 见 §3.3 | **只有 5 个词**：`needs-you` / `working` / `finished` / `idle` / `unknown` |
| `evidence[]` | ✅ | 各家 | 每条 = {来源, 时间, 置信度}；**卡上显示的每个结论都能追到一条证据** |
| `activity` | 可选 | rollout / 时间线 | 最后一句/最后一动作、开始时间、耗时、token、产物 |
| `link` | 可选 | 前端 | 对应的本应用会话 id（能一键切过去）；herdr 还能给"开观察窗" |

**取舍**：`pid`、`exitCode` 这类"只有某些承载才有"的字段**允许多数为空**，界面按空值自适应 ——
**不许用编造值填满**（`App.tsx:418` 的 `herdrAgentToTask` 注释已经立了这条规矩："时长/pid 拿不到就留空 —— 不编"）。

### 3.2 界面分层（从上到下）

```
L0  状态栏（常驻一行）        会话 · 连通性异常 · 「需要你」(带计数) · 传输
L1  AI 面板 · 「需要你」       只放 needs-you；默认展开；没有就不占位（空态一行）
L2  AI 面板 · 「运行中」       放 working；默认展开；显示"怎么知道的"徽标
L3  AI 面板 · 「最近完成」     折叠；**合并时间线**（同一实体只出现一次，展开才看全部）
L4  承载健康                  herdr 服务/工作区、SSH 断开、探测失败 —— **只在异常时出现**
    工具坞                    收进面板标题栏的「＋」菜单（探测/安装/启动仍可用）
```

**为什么这么分**：用户打开面板时想知道的顺序是"有没有事等我 → 在跑什么 → 刚才干完了什么"；
现状把 2 与 3 混在一区、4 常驻、工具坞常驻，等于**每一层都在抢同一块注意力**。
`L4` 只报异常的理由：herdr 服务"运行中 · 3 个窗格"这种正常状态，用户看一眼就再也不需要了。

### 3.3 五种承载怎么统一（关键一节）

**同一套界面、同一套状态词**；差别体现在**能承诺到什么状态**与**来源徽标**：

| 承载 | 状态能到什么精度 | 卡上徽标 | 明确禁止 |
|---|---|---|---|
| **herdr** | `needs-you` / `working` / `finished` / `idle`（第一手，`herdr.rs:225-238`） | `herdr` | — |
| **tmux** | `working` / `unknown`（前台进程 + 日志能佐证"在动"） | `进程 + 日志` | 不许显示 `needs-you`、不许显示百分比 |
| **远端裸 SSH** | `working`（仅有进程）/ `unknown` | `进程` | **永远不显示 `needs-you` / `finished`** |
| **本地 PowerShell** | 同 tmux（进程表 + codex 的 rollout，`ai_sessions.rs:828`） | `进程 + 日志` | 不许把"桌面端 Codex 的日志"当本机任务（`863-895`） |
| **本地 CMD** | `unknown`（"这个会话在"） | `仅状态` | 不许进「运行中」区 |
| **WSL** | 同 tmux（进 WSL 跑 ps，`commands.rs:1719-1747`） | `进程` | 不许把 Windows 侧看不到当成"没有" |

**可信度怎么表达**：徽标 + 悬停写清"这条是怎么得出的"（例：`herdr 第一手 · 12 秒前` / `进程扫描 · 50 秒前，只能说明它在跑`）。
**规矩：推断绝不说成事实**（这条是 ②③ 两次用户误报换来的）。

### 3.4 状态栏该放什么

| 保留 | 理由 |
|---|---|
| 当前会话（模块 · 标题 · 状态） | 唯一"我现在在哪"的锚点（`App.tsx:8341-8346`） |
| 临时提示 `statusMsg` | 操作反馈的落点（`8348-8356`） |
| 「需要你」（带计数，点击切过去/展开面板） | 替代现在的"AI 已完成，点这里切过去" chip（`8359-8373`）；**完成不再单独占一个 chip**，避免与时间线、卡片三处重复 |
| 连通性异常（SSH 断开/重连中） | 现在散在会话状态里，值得提到全局一行 |
| 管理员标识 | 安全相关，保留（`8374-8381`） |

| 移走 | 去哪 |
|---|---|
| `UTF-8`、`xterm-256color` | 终端右键 →「会话信息」（想看的人能找到，不占常驻位置） |
| 当前文件路径（`8357`） | 已有标签栏，重复 |
| AI 完成 chip | 合进「需要你」/「最近完成」 |

### 3.5 噪音控制规则

1. **默认显示**：`needs-you` + `working`；`finished` 保留 **30 分钟**在「最近完成」顶部，之后只在折叠区/时间线里。
2. **`idle` 永不占位**（现状已如此，`isActiveBoardTask` `464-470`，把它写进模型而不是 UI 折叠逻辑）。
3. **陈旧判定**：`working` 超过 **10 分钟**没有任何证据更新 → 降级成 `unknown` 并在卡上写"可能已卡住（10 分钟无更新）"。
4. **通知**：只两条 —— ① 某个实例进入 `needs-you`；② 一轮跑完**且产出新文件**（受 `aiNotifyDocs` / `aiNotifyAllArtifacts` 控制，`App.tsx:707-710`）。
   去重键 = `实例 id + 事件类型 + 轮次`（把现在的 `herdrNotified` / `aiHandledTurns` 合成一个）。
5. **探测失败要能区分**：面板 L4 只在"上次能用、这次探测失败"或"从来没探到但用户点过探测"时出现一行，写清失败原因（网络/未安装/herdr 版本太旧，`App.tsx:1450` 已有 `too_old` 概念）。

### 3.6 状态 × 动作（每张卡上的按钮由状态决定）

| 状态 | 主按钮 | 次按钮 | 说明 |
|---|---|---|---|
| `needs-you` | **切过去**（有会话）/ **接管**（herdr 可写） | 开观察窗（只读） | 最值钱的一路信号（`App.tsx:1512-1513` 注释） |
| `working` | 切过去 | 开观察窗 | 没有会话时只给"开观察窗"（herdr） |
| `finished` | 看产物（打开文件） | 切过去 | 产物来自 rollout（`ai_sessions.rs:689`）或时间线 |
| `idle` | 切过去 | — | 默认不占位，出现在折叠区时才有 |
| `unknown` | 切过去（若有会话） | — | 没有会话时**不给按钮**（不给假承诺） |

### 3.7 这次我们放弃了什么（换来了什么）

|---|---|
| 卡片区显示"所有历史窗格" | 「需要你」永远在最上面，不被陈旧窗格挤下去 |
| 三套状态词的细腻差别（如 herdr 的 `idle` 与"没探测到"） | 一套 5 词表，用户不用翻译 |

## 9. 给用户的一屏简报（请先读这一节）

### ① 现在乱在哪（3 条）

1. **同一件事说了三遍**：卡片区、面板里的「最近任务」、状态栏那条"AI 已完成" —— 三处都能看到"跑完了"。
2. **"它说的"和"我们猜的"长得一模一样**：herdr 给的是第一手状态，进程扫描只能证明"有这么个进程"，
   但界面上两种卡同形、不标来源 —— 于是"探测到我的 PowerShell 里有 Codex"这种误读发生过两次。
3. **该抢注意力的和不该抢的混在一起**：陈旧窗格、herdr 服务正常行、工具坞常驻，都在跟"有人等你处理"抢位置。

### ② 新方案长什么样（从上到下）

最上面那行状态栏只说四件事：**我在哪个会话、有没有断线、有没有人等你（带计数）、有没有文件在传**。
打开 AI 面板，第一眼是**「需要你」**（只有真的要你回话的才在这，没有就一行空态）；
往下是**「运行中」**（每张卡右上角一个小徽标，写这条是 herdr 说的还是进程扫出来的，鼠标停上去能看到"多久之前、怎么得出的"）；
再往下是**「最近完成」**，默认折起来，展开就是原来的时间线（同一件事不会再在别处重复一遍）。
herdr 服务、连通性这类"健康信息"平时不出现，**只在出问题时冒一行**。工具坞收进标题栏的「＋」。

兼容上：本地 PowerShell / CMD / WSL、远端裸 SSH / tmux / herdr —— **同一套界面**。
区别只在"能说多准"：herdr 能说"它在等你"，裸 SSH 只能说"它在跑"，
**说不了的就老实写"只能看到它在跑"，绝不编**。

### ③ 已经拍板了（最终口径见 §10）

用户已经拍板 **7 条**；**以 §10「最终口径」为准**，它优先于本文其它地方。

## 10. 最终口径（用户已拍板 · 这一节优先于本文其它地方）

> 实现时只认这一节；与 §3 / §4 / §9 冲突处**以本节为准**（冲突清单见 10.9）。
> 每条格式：**用户要什么 / 界面表现 / 验收断言 / 不能回退什么**。

### 10.1 删掉独立的「最近任务 / 时间线」列表

- **用户要什么**：界面上不要再有那个列表（原话："AI 的任务列表我觉得也太乱了，可以不要了吧"）。
- **界面表现**：看板上只留**折叠一行** `▸ 最近完成 N 项`，点开才展开；**数据继续落盘**（不显示 ≠ 丢掉）。
- **验收断言**：面板里不存在常驻时间线容器；`▸ 最近完成` 默认折叠（展开前明细不可见）；落盘文件仍在写。
- **不能回退什么**：完成项仍能看到"谁 / 什么时候 / 有什么产物"（点开后）。

### 10.2 面板默认只有两个区

- **用户要什么**：打开面板第一眼只有「需要你」和「运行中」（"面板默认只有两个区 可以的"）。
- **界面表现**：`需要你` + `运行中`；`最近完成` 与 `空闲` **各折成一行**；**承载健康只在异常时出现**。
- **验收断言**：无异常时**不渲染**承载健康行；`needs-you` 区排在 `working` 区之前；空态只有一行字。
- **不能回退什么**：异常（探测失败 / 断线）必须看得见 —— 只是不常驻。

### 10.3 状态栏只留四件事

- **界面表现**：`会话 · 连通性 · 需要你 N · 传输`；`UTF-8` / `xterm-256color` / 窗口尺寸**收进悬停**（或右键「会话信息」）。
- **验收断言**：状态栏文本**不含** `UTF-8` 与 `xterm-256color`；悬停/右键里能找到它们；没有上传时不出现传输段。
- **不能回退什么**：这四类信息本身不能丢。

### 10.4 裸 SSH 永不显示「等你处理」

- **界面表现**：裸 SSH 的卡只写「运行中（进程推断，可能已卡住）」。
- **验收断言**：mock 裸 SSH 会话下，**任何情况下不出现 `needs-you`**（包括"输出停了"）。
- **不能回退什么**：将来接了 OSC 7501，这条**允许升级**（见 10.7）—— 变成"有自报才显示"。

### 10.5 没跑 agent 的承载不上板

- **界面表现**：CMD 等空承载**不在看板占行**，只在「承载健康」的悬停里可查。
- **验收断言**：mock CMD 会话**不产生任何卡片行**；「承载健康」悬停里能找到它。
- **不能回退什么**：用户仍能查到"我开了哪些承载"。

### 10.6 红点 / 通知规则（本轮新增，最重要）

- **用户要什么**：最左侧 AI 按钮的红点**别吵** —— 只有两件事值得亮。
- **亮**：
  1. **需要你**（等你批准 / 输入）→ 红点**亮到你处理为止**；
  2. **这一轮跑完、有结果、而且停下来了**（不再跑）→ **点开面板即清**（当"未读"）。
- **不亮**：运行中、空闲、陈旧、**只产出文件但还没停**、探测不到。
- **去重**：**同一实例、同一轮只亮一次**（按轮次去重；反复刷新/轮询不能让它又冒出来）。
- **设置里同步**：把现在那条"跑完了"的说明**拆成两个独立开关** ——
  `☑ 需要你处理时提醒`、`☑ 跑完一轮并停下时提醒`（默认都开），并用大白话写明规则：
  "需要你 → 亮到你处理；跑完停下 → 点开就消"，下面一行灰字"其它情况不提醒"。
- **验收断言**：① `needs-you` → 红点出现且**打开面板后仍亮**，直到该实例不再是 needs-you；② `finished` → 红点出现、**打开面板即清**；③ 同一轮重复轮询 → **只发生一次**；④ `working` / `idle` / 仅产物事件 → **红点不变**；⑤ 设置页恰有这两个开关、默认都开。
- **不能回退什么**：不能为了"降噪"把**需要你**漏掉 —— 那是唯一真正值得打断用户的事。

**实现口径（2026-10-20 落地，用户当场拍板）**：红点只允许来自"能**直接读**"的来源，
**手动刷新得到的任何数据都不算**（用户原话："手动刷新出现红点这种宁可不要"）。

| 来源 | 自动亮？ | 怎么拿到 |
|---|---|---|
| 本机 codex rollout 日志 | ✅ | `core/ai_log_watch.rs`：2.5 秒 `stat` 一次，只读**新增字节**，**不启动子进程**；→ `zeeai://ai-log` |
| 本应用启动的任务（账本） | ⚠️ 本机算 / 远端不算 | 本机 codex 走上面那条日志；远端账本没有"进程结束"事件，不探测就不知道 |
| herdr 接管窗格 | ✅（2026-10-20 用户批准） | `core/ai_herdr_dots.rs`：**每台 `herdrEnabled` 的服务器每 60 秒**跑一次已有的 `commands::herdr_agents`（→ `run_remote_capture` → `proc::hidden_command_async`，带 `CREATE_NO_WINDOW`，不弹黑框）；启动后先等 12 秒，失败静默（只 `log::warn`）；→ `zeeai://ai-log` |
| 进程扫描 / `ssh ps` / tmux / 裸 SSH / CMD | ❌ | 只证明"存在"，不产生红点 |
| 手动「刷新」 | ❌ | `refreshAiPanel` / `refreshBoard` **只更新卡片/看板**，不设置红点 |

herdr 那一路的判定：`blocked` = **状态**（亮到它不再是 blocked，那一次发 `resolved`）；
`done` = **事件**（只在"进入 done"的那一次亮，用每个窗格上一轮的状态做边沿检测；
持续 done / 第一次看见就是 done 都不亮）；`working` / `idle` 不亮；
状态回退（done → working）之后再 done 可以再亮一次。没有 `herdrEnabled` 的服务器
**一个请求都不发**。

**卡片也自动更新（2026-10-20 第二轮，用户拍板）**：红点之外，上面两路"能直接读"的
来源同时驱动**卡片**，这样没点「刷新」也能看到正在跑的 AI：

| 事件 | 谁发 | 带什么 | 前端怎么用 |
|---|---|---|---|
| `zeeai://ai-log` | `core/ai_log_watch.rs`（+ herdr 红点信号） | 原红点字段 + `instanceKey` / `state` / `activity` | 红点逻辑不变；带 `instanceKey` 的那条再按**实例身份**更新/创建卡片 |
| `zeeai://herdr-agents` | `core/ai_herdr_dots.rs`（60 秒那轮的副产品） | 该服务器每个窗格的 `pane/status/agent/cwd/workspace/tab/title` + 统一 `state` | 就地更新/创建 herdr 卡片；不碰红点 |

三条边界：① 两个事件都**不调** `ai_instances`（那等于把「刷新」自动点一遍，会起进程 / ssh）；
② 对已有卡片只改 `state` / `activity` / 时间 / 徽标，`where` / 证据 / 产物等
"刷新拿到的完整字段"不动；③ 点「刷新」后一律以 `ai_instances` 的全量结果为准
（自动建的卡被替换，徽标末尾那个「自动更新」也会消失）。

去重键：本机日志 = `log|<rollout 文件名>|<turn_id>`；herdr = `herdr|<服务器配置 id>|<窗格>`。
`needs-you` 与 `resolved` 用同一个 key 配对；本机日志的 `finished` 只在该轮的
`completed_at` 往前走时发一次，herdr 的 `finished` 只在进入 done 的那一次发一次。

### 10.8 与既有承诺的关系

- 时间线**仍然落盘**（`ai_history.rs`）：不显示 ≠ 丢掉，将来要做"历史/统计"另开一页；
- herdr / tmux / 本地 PowerShell / 裸 SSH 的能力差异照旧**如实表达**（徽标 + 悬停）。
- **本机 AI CLI 健康检查（看板异常位 + 一键修）：已取消，不要再加回来。**
  它在 0.1.12 里做过一版，但每 20 秒自动探测会在 Windows 上反复拉起
  `where` / `--version` / `powershell` 子进程 —— 应用是 GUI 进程，缺 `CREATE_NO_WINDOW`
  就弹一个**控制台黑框**，坐在电脑前的用户被持续打断（真机报障）。
  整条功能已删除（后端模块与三个 IPC 命令、前端看板块 / 状态栏 chip / 设置字段、
  单测与无头断言都不再有它）。
  **承载健康现在只剩 herdr 那一路**（服务 / 工作区 / 探测失败），口径仍是"只在异常时出现"；
  以后若要做本机探测，必须先读 `src-tauri/src/core/proc.rs`：后台子进程一律走
  `hidden_command`（`CREATE_NO_WINDOW`），**不许**裸 `Command::new`，也不要把探测塞进
  短周期定时器。
